# Выпуск и обновление Сёмы

Pull request и основная ветка проходят сборку, vet, Go-тесты, браузерные проверки
настроек и сканирование секретов. Из проверенного коммита `main` создаётся выпуск
`build-<SHA>`. В GitHub Releases доступны `sema-linux-amd64.tar.gz`,
`sema-linux-arm64.tar.gz`, `SHA256SUMS` и скрипт обновления.

На хосте Docker скачайте `sema-update.py` из релиза и сверьте его SHA256 по
`SHA256SUMS`. Проверьте источник и доступность нового выпуска командой
`python3 sema-update.py`. Запустите с `--apply`, чтобы установить его. Если в
Docker другое имя контейнера или адрес здоровья, передайте `--container` и
`--health-url`.

Обновляющий процесс проверяет контрольную сумму, которую GitHub возвращает для
архива, и запускает новый бинарник с прежними томами и окружением. При сбое
снова запускается прежний контейнер. Расписание запускается от пользователя,
у которого есть доступ к Docker. Пример строки cron с установленным скриптом:

```cron
*/15 * * * * /usr/bin/python3 /opt/sema/sema-update.py --apply
```

Для извещений задайте в Actions переменную `SEMA_RELEASE_WEBHOOK_URL` со значением
`https://<адрес Сёмы>/api/webhooks/github-release` и секрет
`SEMA_RELEASE_WEBHOOK_SECRET`. Тот же ключ должен быть в окружении контейнера.
Обновляющий скрипт принимает путь к его файлу через `--webhook-secret-file`.
Сигнал появляется в «Уведомлениях». Хост проверяет GitHub независимо от доставки
сигнала.

В «Настройки → Работа Сёмы → Обновления» видны адрес webhook, репозиторий,
текущая версия и состояние немедленной проверки. Для запуска по webhook
выполните на Docker-хосте `docker exec sema mkdir -p -m 700 /data/.release-webhook`.
Установите шаблоны `deploy/sema-update-webhook.path` и `.service` в
`/etc/systemd/system/`. В `.path` подставьте вместо `@VOLUME@` поле `Source`
тома `/data` из `docker inspect sema`. В `.service` подставьте `@UPDATER_USER@`,
`@UPDATER@` и `@KEY@` для того же пользователя, скрипта и ключа, которые уже
использует cron. Примените `systemctl daemon-reload` и
`systemctl enable --now sema-update-webhook.path`.

Webhook запускает проверку сразу. Строка cron выше обеспечивает резервную
проверку каждые 15 минут. Выключатель в настройках управляет запуском по
webhook. Обе проверки используют одну блокировку. Журнал немедленной проверки
доступен через `journalctl -u sema-update-webhook.service`.
