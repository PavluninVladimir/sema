# Команды

Сборка, запуск, проверки, копия и восстановление. Все команды сервера
выполняются из папки `server/`. Адреса и имена в примерах — образцы:
`sema.local` — имя машины в домашней сети, `sema` — имя контейнера,
`sema-data` — именованный том.

## Что нужно

- Go той версии, что в `server/go.mod`. cgo не нужен нигде.
- Для разбора PDF — `pdftotext` (пакет poppler-utils).
- Для распознавания картинок на Linux — tesseract с языками `rus` и `eng`.
  На macOS Сёма собирает помощника на Swift поверх Vision сам, если есть
  `swiftc` (Xcode Command Line Tools).
- Docker — если запускать в контейнере (так проще всего: в образе уже есть
  poppler, tesseract и sqlite).

## Сборка

```sh
make build     # бинарник sema-server для этой машины, версия из git
make linux     # x86-64 Linux: sema-server-linux-amd64
make pi        # ARM64 Linux (Raspberry Pi, ARM-VPS): sema-server-linux-arm64
make docker    # образ sema:latest под текущую архитектуру
make sums      # SHA256SUMS к собранным файлам
```

Собирать лучше через `make`: версию подставляет линковщик
(`internal/version.Version`), без неё сервер называет себя «dev», и на
«Здоровье», в `-doctor` и в ссылке на исходный код это видно. Везде
`CGO_ENABLED=0` — один статический бинарник.

Отпечаток образа: `docker image inspect sema:latest --format '{{index
.RepoDigests 0}}'`. Проверка архитектуры бинарника внутри образа — в
`PITFALLS.md` («У `ARG TARGETARCH` нет значения по умолчанию»).

## Запуск

### Ключ шифрования

Секреты (ключи моделей, пароли ящиков, токены, ключи SSH) шифруются ключом
из переменной `SEMA_KEY`. Без ключа Сёма поднимается, но секреты не
принимает. Ключ — любая длинная случайная строка:

```sh
openssl rand -base64 32
```

Храните его вне каталога данных (например, в `.env` рядом с
`docker-compose.yml`, права только владельцу, файл — в `.gitignore`). В
базу, в образ и в резервную копию ключ не попадает намеренно: копия без
ключа неполна. Потеряли ключ — секреты не прочитать.

### Docker

```sh
docker build -t sema:latest .
docker volume create sema-data
docker run -d --name sema --restart unless-stopped \
  -p 127.0.0.1:8765:8765 \
  -v sema-data:/data \
  -e SEMA_KEY="$SEMA_KEY" \
  -e SEMA_LISTEN=0.0.0.0:8765 \
  --stop-timeout 150 \
  sema:latest
docker logs sema          # здесь адрес входа и код первой установки
```

- Внутри контейнера сервер слушает `0.0.0.0:8765` (`SEMA_LISTEN`), а наружу
  порт опубликован только на loopback хозяина. Пускать в сеть —
  через обратный прокси с TLS или по защищённому порту (ниже).
- Данные — только в **именованном томе**. Bind-mount папки хозяина на маке
  не передаёт блокировки SQLite, и база повреждается (см. `PITFALLS.md`).
- `--stop-timeout` (в compose — `stop_grace_period`) заметно больше
  мягкого срока остановки `stop.soft_s` (30 с): иначе Docker убьёт процесс
  раньше, чем Сёма закроет базу начисто.
- Папка хозяина как источник файлов: `-v <папка>:/data/inbox`, затем
  «Хранилища → Откуда берутся» → наблюдаемая папка `/data/inbox`.
- Модели на хозяине (LM Studio, Ollama), записанные в настройках как
  `127.0.0.1`: `-e SEMA_HOST_ALIAS=host.docker.internal` — адрес подменяется
  в момент обращения, настройки не меняются.
- Модели в своих контейнерах: контейнер Сёмы — в той же сети Docker
  (`--network <сеть>`), иначе их имена не разрешаются.
- Житель машины звонит на отдельный порт (`agents.listen`, например
  `0.0.0.0:8766`, задаётся на экране «Агенты»): его тоже надо опубликовать,
  `-p 8766:8766`.

Пересборка и замена контейнера:

```sh
docker build -t sema:latest . && docker rm -f sema && docker run … # как выше
```

Пересоздавая контейнер, переносите тома, переменные **и сети**.

Тот же запуск через compose: `docker compose up -d` по
`server/docker-compose.yml`, ключ — в `.env` рядом (образец —
`.env.example`).

### Без Docker

```sh
./sema-server -data ./data                 # или: go run ./cmd/sema -data ./data
./sema-server -config config.yaml          # или: make run
```

Файл запуска (`config.example.yaml`) содержит только то, что нужно раньше
базы: адрес, каталог данных, имя переменной с ключом. Всё остальное —
ящики, модели, пороги — настраивается на экранах и живёт в базе. Файла
может не быть вовсе: Сёма поднимется пустым и покажет мастер первого
запуска. Необязательная заготовка ящика и модели в файле один раз
переносится в базу при первом старте.

Переменные окружения важнее файла, флаг `-listen` важнее всего:

| Переменная | Что задаёт |
|---|---|
| `SEMA_LISTEN` | адрес HTTP, по умолчанию `127.0.0.1:8765` |
| `SEMA_DATA` | каталог данных: база `sema.db`, файлы, служебные файлы |
| `SEMA_KEY` | ключ шифрования секретов или фраза восстановления |
| `SEMA_KEY_ENV` | имя переменной с ключом, если не `SEMA_KEY` |
| `SEMA_TLS_CERT`, `SEMA_TLS_KEY` | сертификат и ключ защищённого порта (файлы на машине) |
| `SEMA_TLS_LISTEN` | адрес защищённого порта (`:8443`); у новой установки — только loopback |
| `SEMA_HOST_ALIAS` | имя хозяина вместо `127.0.0.1` в адресах моделей (Docker) |
| `SEMA_TOKEN` | токен доступа для `semacheck perf`, хуков и инструментов |

Занятый порт — отказ с диагностикой, кто его держит, а не переезд на
другой порт: порт входит в адрес входа passkey.

### Первый вход

Клиент — браузер: `http://localhost:8765` на самой машине (или
`https://sema.local:8443`, когда настроен защищённый порт). Сёма ставится
как PWA; на телефоне — «Добавить на экран „Домой“».

У новой установки вход закрыт: без ключа пускается только сама машина
(loopback). Первый ключ passkey заводится:
- с самой машины — браузер на ней же открывает `http://localhost:8765`;
- или по **коду первой установки**: пока ключей нет, Сёма при каждом старте
  печатает одноразовый код и адрес входа в стандартный вывод. В Docker это
  `docker logs sema`, у службы — её журнал. Код вводится на странице входа
  и открывает сессию только на заведение ключа; умирает после первого
  ключа, по сроку и при перезапуске.

Дальнейшие ключи и токены заводятся из сессии на «Настройки → Вход и
доступ». Пускать частную сеть без ключа можно только явным выбором там же.

### Gmail

```sh
go run ./cmd/sema -google-login     # разовый вход в Gmail по OAuth, токен ляжет в базу
```

OAuth-клиент типа «Desktop app» создаётся в Google Cloud Console (APIs &
Services → Credentials); его ключи вводятся на экране ящика, вкладка
«Подключение». Сам вход — один раз из терминала на машине с браузером:
команда откроет окно согласия и сохранит токен в базе. Для Яндекса и других
ящиков достаточно пароля приложения на экране «Почта».

## Самоосмотр

```sh
./sema-server -doctor -data /путь/к/данным
```

Каталог, замок, база, ключ, порт, инструменты. Работает и когда Сёма не
поднимается — этим и ценен. В контейнере:

```sh
docker run --rm -v sema-data:/data -e SEMA_KEY="$SEMA_KEY" \
  --entrypoint /usr/local/bin/sema sema:latest -doctor -data /data
```

## Резервная копия и восстановление

```sh
./sema-server -backup копия.tgz [-no-files] -data /путь
```

Копия снимается с работающей Сёмы: база, файлы, опись с sha256 и
счётчиками; рядом ложится `копия.tgz.sha256`. Ключ шифрования в копию не
кладётся. `-no-files` — без файлов вложений. В контейнере:

```sh
docker run --rm -v sema-data:/data -v "$PWD":/out -e SEMA_KEY="$SEMA_KEY" \
  --entrypoint /usr/local/bin/sema sema:latest -backup /out/копия.tgz -data /data
```

```sh
./sema-server -restore копия.tgz -data /путь      # Сёму остановить
```

Восстановление сначала осматривает копию — хэши, `integrity_check`,
миграции, расшифровку ключом из `SEMA_KEY`, счётчики — и только потом
кладёт базу в каталог.

После `-restore` Сёма стоит в состоянии «нужна привязка» (маркер
`восстановлено.txt`): почта, папки, переносы и зеркало файлов не
запускаются, пока на «Здоровье» не нажать «Это его новое место». Иначе
копия и оригинал отбирали бы письма друг у друга.

Только база, без файлов и описи: `docker cp sema:/data/sema.db
./backup.db` (сервер лучше остановить).

Копии можно выгружать на Яндекс.Диск родным API: `-yadisk-put <файл>`,
`-yadisk-list`, `-yadisk-rm <имя>`; папка — `-yadisk-dir`, OAuth-токен —
секрет, имя которого задаёт `-yadisk-token`.

## Смена ключа шифрования

```sh
./sema-server -rekey -fresh-backup копия.tgz -data /путь
```

- Нужна копия не старше часа, Сёма остановлена.
- Перешифровка идёт на снимке базы.
- Команда печатает новую фразу восстановления (24 знака и контрольная
  группа). Сёму дальше запускать с этой фразой в `SEMA_KEY`.
- Копии, снятые до смены, открываются прежним ключом.

## Потеря всех ключей входа

```sh
./sema-server -reset-auth -data /путь    # Сёму остановить
```

Удаляет все passkey и сессии. После запуска вход снова как у новой
установки: с самой машины или по коду первой установки из журнала.
Токены доступа и данные не трогаются.

## Работа с базой

Пока сервер в контейнере, база смотрится только изнутри:

```sh
docker exec sema sqlite3 /data/sema.db 'select …'
```

Снаружи к файлу базы не прикасаться: это уже приводило к повреждению.

Против запущенного сервера (с токеном или с самой машины):

```sh
curl -s 'http://127.0.0.1:8765/api/ui?screen=health' | python3 -m json.tool
curl -X POST http://127.0.0.1:8765/api/action \
  -H 'Content-Type: application/json' \
  -d '{"action":"…","target":"…","params":{}}'
```

## Диагностика на живых данных — `semacheck`

Из `server/`, с тем же `SEMA_KEY`, что у сервера, и тем же каталогом
данных (`SEMA_DATA` или `config.yaml`):

```sh
go run ./cmd/semacheck folders                 # папки ящика: счётчики, непрочитанные, что разбираем
go run ./cmd/semacheck locate '<message-id>'   # в какой папке письмо лежит сейчас
go run ./cmd/semacheck parts  '<message-id>'   # части письма и вложения так, как их видит Сёма
go run ./cmd/semacheck probe  '<папка> <message-id>'  # как сервер ищет письмо в папке
go run ./cmd/semacheck move   '<message-id> <папка>'  # вернуть письмо в папку
go run ./cmd/semacheck rag 'вопрос'            # ровно тот контекст, который уйдёт модели
SEMA_MODEL=<модель> go run ./cmd/semacheck rag 'вопрос'   # глазами конкретной модели
go run ./cmd/semacheck module '<имя>'          # выполнить модуль с его правами
go run ./cmd/semacheck module-parse ответ.md   # как Сёма разберёт блок sema-module в ответе модели
go run ./cmd/semacheck key                     # подходит ли SEMA_KEY к базе
SEMA_ACCOUNT=<ящик> go run ./cmd/semacheck locate '<id>'  # любой ящик, не только основной
```

`SEMA_MODEL` полезен, чтобы увидеть, что недоверенная модель не получает
закрытых ящиков и секретного.

## Замер скорости экранов

```sh
SEMA_TOKEN=… go run ./cmd/semacheck perf -base http://127.0.0.1:8765 [-dir ~/.sema-perf] [-phone]
```

Обход от меню и разделов, три запроса на экран. Экраны просятся режимом
подогрева (`X-Sema-Prefetch`): ничего наружу не уходит, экран, которому
нужна сеть или житель машины, отвечает 204 и считается пропущенным; чаты и
«Почту» замер не трогает. След остаётся — строка «Кто стучался» на каждый
запрос по токену. Итог — таблица и JSON рядом с прошлыми прогонами с
разницей «было → стало» и нагрузкой машины до и после.

Мерить на самой машине Сёмы (loopback): по Wi-Fi в цифры попадает сеть.
Токен передавать через окружение или stdin, а не строкой в команде.
Бинарник под ARM: `GOOS=linux GOARCH=arm64 go build -ldflags "-s -w"
./cmd/semacheck`.

Разбор одного ответа:
- заголовок `Server-Timing`: `menu`, `build`, `render`, `sql` с числом
  запросов, `sqlmax` — самый долгий запрос;
- сам долгий запрос — строкой в журнале сервера, когда он дольше
  `debug.slow_sql_ms` (50 мс): шаблон без значений и цепочка «метод
  хранилища ← движок ← экран» (`docker logs sema | grep 'медленный запрос'`);
- профилировщик — `/debug/pprof` по настройке `debug.pprof` (вход только с
  правом «всё»; пока включён — строка тревоги на «Здоровье»).

## Проверки

```sh
go test ./internal/...                                   # всё
go vet ./...
go test ./internal/engine -run XXX -fuzz FuzzClassify -fuzztime 30s
```

Фаззинг есть у `FuzzClassify`, `FuzzSentClass`, `FuzzExtractModuleBlock`,
`FuzzParseTimerDuration`; найденные случаи ложатся в
`internal/engine/testdata/fuzz/`.

Веб-клиент в настоящем Chrome (chromedp, без node):

```sh
SEMA_BROWSER=1 go test ./internal/api -run Browser -p 1 -timeout 45m
```

Срок нужен: суита идёт около двух минут, но стандартных десяти минут на
весь прогон не хватает, и падает он дампом горутин, а не тестом. `-p 1` —
иначе Chrome не поспевает и тесты плавают.

Разметка одного экрана в файл:

```sh
SEMA_PAGE_OUT=/tmp/p.html SEMA_PAGE_SCREEN=health go test ./internal/api -run DumpPageToFile
```

Что покрыто тестами:
- табличные тесты разбора (`engine/parse_test.go`, `engine/audit_test.go`);
- проверки свойств на сгенерированных случаях — правила SSH-команд
  (`engine/ssh_property_test.go`, судит настоящий `Engine.Classify`, а не
  копия правил) и очередь «ничего не теряется» (`store/store_test.go`);
- фаззинг (выше);
- интеграционные сценарии на временной базе с поддельной моделью
  (`engine/integration_test.go`); поддельная модель отчитывается через
  `llm.Report` — тем же путём, что настоящие провайдеры;
- сборка всех экранов (`api/screens_test.go`) и сверка словаря UI-DSL
  (`api/dictionary_test.go`);
- регрессии безопасности (`api/security_regress_test.go`,
  `engine/security_regress_test.go`).

Тесты не заменяют проверку на живых данных: почта, модели и OCR ведут
себя не так, как ожидается. Изменение поведения проверяется против
запущенного сервера — `curl` к `/api/ui` и `/api/action`, `sqlite3` в
контейнере, `semacheck`.

## Документация не врёт про имена

Переименовали символ — проверьте, что `docs/` не уводит к имени, которого
больше нет (компилятор документацию не видит). Из корня репозитория:

```sh
grep -ohE '[A-Za-zА-Яа-яЁё_][A-Za-zА-Яа-яЁё0-9_]{4,}' docs/*.md \
  | grep -E '[a-z][A-Z]' | sort -u > /tmp/doc.txt
grep -rohE '[A-Za-zА-Яа-яЁё_][A-Za-zА-Яа-яЁё0-9_]{4,}' \
  --include='*.go' --include='*.js' --include='*.css' server \
  | sort -u > /tmp/code.txt
comm -23 /tmp/doc.txt /tmp/code.txt
```

Проза отсеивается признаком camelCase (заглавная не в начале слова). Слабое
место проверки: она ищет упоминание, а не объявление, и мёртвое имя,
оставшееся в комментарии кода, считает живым.

## Житель машины

Сборка, установка и подключение к агентам разработки — в README
репозитория `sema-agent`. Коротко:

```sh
make build
semaagent -enroll <код> -role житель -sema http://sema.local:8765   # разовый вход к Сёме
semaagent -link sema.local:8766                                     # демон: провод и местная дверь
```

Одноразовый код выдаёт экран «Агенты» в Сёме.
