# Sema · Сёма

**Sema** is a self-hosted personal assistant. One Go server (no cgo, one
static binary for x86-64 and ARM) with a built-in web client. It watches
your mailboxes over IMAP and filters spam, reads documents, receipts and
QR codes, keeps a long-term memory, works with Telegram and MAX, runs
JavaScript modules in a sandbox, manages your servers over SSH under
explicit allow / ask / deny rules, and connects to MCP servers. It uses
local or cloud language models through a single gate: nothing classified
as secret ever reaches a model you have not marked as trusted.

**The user interface and the documentation are in Russian only.**

Quick start with Docker (no prebuilt image is published — build it from
the `Dockerfile`):

```sh
git clone https://github.com/PavluninVladimir/sema
cd sema/server
docker build -t sema:latest .
docker volume create sema-data
export SEMA_KEY="$(openssl rand -base64 32)"   # encrypts your secrets; store it safely
docker run -d --name sema --restart unless-stopped \
  -p 127.0.0.1:8765:8765 -v sema-data:/data \
  -e SEMA_KEY="$SEMA_KEY" -e SEMA_LISTEN=0.0.0.0:8765 sema:latest
docker logs sema                                 # sign-in address and one-time setup code
```

Open `http://localhost:8765`. A fresh install is closed by default: the
first passkey can be registered only from the machine itself or with the
one-time setup code printed to the container log.

The companion daemon for your workstation (code intelligence for coding
agents, memory, desktop notifications) lives in
[`sema-agent`](https://github.com/PavluninVladimir/sema-agent).

## Что это

Сёма — личный ассистент, который живёт у вас: на домашнем сервере, на
Raspberry Pi, на VPS или на ноутбуке. Это один сервер на Go и веб-клиент,
который приезжает вместе с ним и ставится как приложение (PWA) на
компьютер и телефон. Данные — в одной базе SQLite в вашем каталоге.

Сёма работает с языковыми моделями — своими (LM Studio, Ollama,
llama.cpp) или облачными (OpenAI, Anthropic, DeepSeek, Google Gemini,
Groq, OpenRouter, Perplexity и любой OpenAI-совместимый адрес) — но
решает сам, что модели можно показать. Модель, которой вы не доверили
закрытое, не получает ни секретного, ни писем из закрытых ящиков, и
каждая отправка видна на экране «Что ушло наружу».

Интерфейс и документация — только на русском.

## Что умеет

**Почта.** Следит за ящиками по IMAP (Gmail по OAuth, Яндекс и другие по
паролю приложения), разбирает спам и спрашивает только о сомнительном,
запоминает решения правилами по отправителю, учится у спама почтового
провайдера. «Почта» открывается сводкой «что пришло» по группам. Письма из
архива Сёмы не удаляются никогда — удаление касается только почтового
сервера. Рабочий ящик можно закрыть от облачных моделей или поставить в
режим «только читать».

**Файлы и чеки.** Вложения, загрузки, наблюдаемые папки и страницы из
интернета складываются в одно хранилище с дедупликацией; копия — в S3 по
желанию. Текст достаётся из PDF, офисных документов и картинок (OCR).
Сумма, продавец и срок оплаты ложатся в поля файла; QR кассового чека,
маркировка «Честного знака» и штрих-коды читаются самим сервером, без
модели. Файл можно отдать ссылкой с подписью и сроком.

**Чат и память.** Разговор с Сёмой видит опись того, чем он располагает,
письма и файлы по смыслу, память о прошлых разговорах. Память — факты,
уроки и сводки сессий с графом связей, областями доступа и масками
секретов; Сёма может сам разбирать и подтверждать свои записи. Большие просьбы
становятся поручениями, которые Сёма ведёт по шагам до готовности.

**Уведомления.** Всё, что ждёт решения, — в одном списке: команды на
подтверждение, сроки из писем, бюджеты, сменившиеся отпечатки серверов.
Доставка — пуши в браузер и на телефон (без содержимого писем), значок у
часов на маке через жителя машины, модули.

**Серверы.** Команды по SSH только по ключам (паролей Сёма не хранит), с
правилами «Разрешить / Спросить / Запретить» у каждого сервера. Не подошло
ни одно правило — запрещено. Есть уровни самостоятельности: «под судом
двух моделей» и «полная» с ночной сменой и страховкой возврата; по
умолчанию ночная смена работает вхолостую и только показывает, что
собиралась сделать.

**Скрипты и модули.** Модули на JavaScript выполняются в песочнице (goja):
права выдаёт человек поимённо, невыданное в песочницу физически не
кладётся. Модули приносят свои задачи, экраны, инструменты и обработчики
событий; Сёма может написать или дописать модуль из чата и проверить его
до установки. Скиллы — инструкции Сёме на русском, которые подмешиваются
в разговор по приметам; Сёма предлагает новые скиллы по итогам сложной
работы, но в промпт они попадают только после вашего согласия.

**Мессенджеры.** Telegram от вашего аккаунта (MTProto, без бота): архив
переписки, ветки обсуждения с Сёмой под любым разговором, админ-чат, из
которого можно управлять Сёмой, ответы с живым набором текста. Публикация
в каналы из модулей. MAX — личные чаты.

**Интеграции.** Клиент MCP с входом OAuth (Streamable HTTP): инструменты
подключённых серверов видны модели в чате и модулям, изменяющие вызовы
ждут кнопки. Поиск в интернете — ролью модели или через SearXNG.

**Учёт.** Каждый вызов модели — в журнале расхода с токенами и деньгами,
цены провайдеров проверяются со страниц провайдеров, остаток на счёте,
бюджеты с предупреждением или паузой, «Здоровье» с пульсом сервера.

## Как устроено

```
 браузер (PWA) ──HTTP, WebSocket──►  сервер Сёмы (Go, SQLite)  ──IMAP──► почта
                                     │  дверь к моделям          ──HTTP──► модели
                                     │  песочница модулей        ──SSH───► серверы
                                     │  память, файлы, очередь   ──MCP───► серверы MCP
                                     ▲
           TLS 1.3 со взаимной проверкой (звонит житель)
                                     │
 житель машины (sema-agent) ── MCP по stdio, хуки ──► агенты разработки
```

Сервер присылает клиенту описание экрана, а клиент его рисует, не зная
предметной области: новая возможность — это новые компоненты на сервере.
Фоновая работа идёт через одну очередь, которая бережёт слабую машину:
локальная модель на Raspberry Pi занимает процессор целиком.

Подробности — в `docs/`:
- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — устройство целиком;
- [`docs/COMMANDS.md`](docs/COMMANDS.md) — сборка, запуск, проверки,
  копия и восстановление;
- [`docs/PITFALLS.md`](docs/PITFALLS.md) — грабли, на которые уже наступали;
- [`docs/GLOSSARY.md`](docs/GLOSSARY.md), [`docs/NAMES.md`](docs/NAMES.md) —
  словарь узлов и слов для имён в коде.

Требования и изменения ведутся в OpenSpec (`openspec/`), макеты экранов —
в `design/`.

## Запуск в Docker

Готовый образ не публикуется: в нём есть poppler под GPL, и вместе с
образом пришлось бы раздавать исходники пакетов. Образ собирается из
`server/Dockerfile` за пару минут.

1. Соберите образ:

   ```sh
   git clone https://github.com/PavluninVladimir/sema
   cd sema/server
   docker build -t sema:latest .
   ```

2. Придумайте ключ шифрования. Им шифруются ключи моделей, пароли ящиков,
   токены и ключи SSH. В базу и в резервную копию он не попадает; потеряете
   — секреты не прочитать.

   ```sh
   openssl rand -base64 32
   ```

   Положите его в `.env` рядом с `docker-compose.yml` (образец —
   `.env.example`), права — только владельцу.

3. Запустите:

   ```sh
   docker volume create sema-data
   docker run -d --name sema --restart unless-stopped --stop-timeout 150 \
     -p 127.0.0.1:8765:8765 \
     -v sema-data:/data \
     --env-file .env \
     -e SEMA_LISTEN=0.0.0.0:8765 \
     sema:latest
   ```

   Или `docker compose up -d` по `server/docker-compose.yml`.

Данные храните в **именованном томе**, а не в папке хозяина: через
bind-mount на маке не работают блокировки SQLite, и база повреждается. По
той же причине база смотрится только изнутри контейнера:
`docker exec sema sqlite3 /data/sema.db '…'`.

Порт опубликован только на loopback. Снаружи к Сёме ходят через обратный
прокси с TLS, через защищённый порт Сёмы или через шлюз жителя машины
(подробнее — `docs/ARCHITECTURE.md`, разделы 9 и 17).

Полезные дополнения к `docker run` — в `docs/COMMANDS.md`: папка хозяина
как источник файлов, модели на хозяине (`SEMA_HOST_ALIAS`), модели в своих
контейнерах, порт для жителя машины.

## Первый вход

Вход в Сёму — по passkey (WebAuthn): ключ хранит ваш менеджер паролей или
система, при входе он спрашивает отпечаток, лицо или код устройства.

**Новая установка закрыта по умолчанию.** Без ключа её пускает только сама
машина (loopback); запрос из домашней сети видит страницу входа.

Первый ключ заводится одним из путей:
- **с самой машины** — откройте `http://localhost:8765` в браузере на ней же;
- **по коду первой установки** — пока ни одного ключа нет, Сёма при каждом
  старте печатает в журнал одноразовый код и адрес входа:

  ```sh
  docker logs sema
  ```

  В Docker браузер хозяина приходит в контейнер не с loopback, поэтому это
  обычный путь. Введите код на странице входа и заведите passkey. Код
  открывает сессию только для заведения ключа и перестаёт действовать
  после первого ключа, по сроку и при перезапуске. Подбор кода запирается,
  как подбор контрольной фразы.

Дальше ключи для других устройств и токены для инструментов заводятся на
«Настройки → Вход и доступ». Там же можно сделать частную сеть «своей» —
тогда вход без ключа будет у всех в ней, включая соседние контейнеры;
Сёма спросит подтверждение и назовёт, кто получит доступ.

Потеряли все ключи — `sema -reset-auth` при остановленной Сёме удаляет все
passkey и сессии, и вход снова как у новой установки.

Затем мастер первого запуска предложит подключить ящик и модель.

## Без Docker

```sh
cd server
make build
SEMA_KEY=… ./sema-server -data ./data
```

Нужен Go той версии, что в `server/go.mod`; для PDF — `pdftotext`
(poppler), для картинок на Linux — tesseract. Сборки под другие машины:
`make linux` (x86-64), `make pi` (ARM64). Все флаги и переменные — в
`docs/COMMANDS.md`.

## Модели

Модели подключаются на экране «Модели и роли» целым провайдером: ключ
подошёл — все модели провайдера появляются в списке. Работа зовёт не
модель, а роль («Чаты», «Фильтр», «Модули», «Память», «Поиск» и другие),
и роли назначаются модели.

Каждая новая модель заводится **внешней**: она не видит закрытых ящиков,
секретного и личного из памяти. Доверие выдаётся поштучно тумблером на
экране модели. Своя модель в своей сети по умолчанию тоже не доверенная —
доверие решает человек, а не адрес.

Облачная запасная модель зовётся только тогда, когда локальная не
успевает.

## Безопасность

- Вход: passkey, токены с правами, журнал «Кто стучался»; новая установка
  закрыта.
- Секреты зашифрованы ключом из `SEMA_KEY`; модулям выдаются поимённо;
  приватная часть ключа SSH модулю не выдаётся никогда.
- У каждого письма и файла есть класс — обычное, чувствительное, секретное
  — и причина. Секретное наружу не уходит никогда, и держится это
  построением: к модели ведёт одна дверь.
- Команды на серверах и вызовы MCP — по правилам; не подошло ни одно —
  запрещено.

О найденных уязвимостях — по [`SECURITY.md`](SECURITY.md), не в issues.

## Резервная копия

```sh
docker run --rm -v sema-data:/data -v "$PWD":/out -e SEMA_KEY="$SEMA_KEY" \
  --entrypoint /usr/local/bin/sema sema:latest -backup /out/копия.tgz -data /data
```

Копия снимается с работающей Сёмы и содержит базу, файлы и опись с
хэшами; ключ шифрования в неё не кладётся. Восстановление (`-restore`)
сначала осматривает копию и только потом кладёт базу. Смена ключа —
`-rekey`. Всё это — в `docs/COMMANDS.md`.

## Житель машины

Сёма живёт в контейнере или на другой машине, а файлы ваших репозиториев
и языковые серверы — на рабочем компьютере. Житель машины
([`sema-agent`](https://github.com/PavluninVladimir/sema-agent)) делает на
месте то, чего нельзя издалека:
- понимает код через языковые серверы и отдаёт агентам разработки
  карточки вместо целых файлов;
- служит дверью в память Сёмы для агентов разработки (MCP по stdio и хуки
  памяти);
- показывает уведомления Сёмы и значок у часов на маке.

Житель звонит Сёме сам по своему шифрованному проводу; что ему можно,
разрешает человек поимённо на экране «Агенты».
