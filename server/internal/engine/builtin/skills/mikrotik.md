## Осмотр MikroTik (RouterOS)

Роутер отвечает на команды RouterOS, а не Linux: `uname`, `ls`, `cat` дают
`bad command name`. Команда — одна строка, начинается с `/`, разделы через
пробел (`/system resource print`), без `|`, `;`, перенаправлений и
кавычек-скриптов. Печать (`… print`) — разрешена и выполняется сразу; всё
остальное (`set`, `add`, `remove`, `enable`, `disable`) у этого роутера
запрещено, пока для него нет правила «Спросить»: такая команда приходит
человеку карточкой «нет правила» с кнопками завести его. `reboot`,
`upgrade` и сброс конфигурации запрещены правилом «Запретить» — Сёма их не
выполняет никогда.

Проверено: любая команда вида `/раздел … print …` разрешается правилом «Разрешить» (`/* print*`),
включая `print where …` и `print count-only`. Значит весь осмотр роутера
делается без единого вопроса человеку — пользуйся этим и смотри шире, чем
ресурсы и пиры.

### Блок осмотра: что Сёма выполняет сам

Список читается прямо отсюда, каждая строка проверена правилами «Разрешить».
Берётся столько строк сверху, сколько разрешает настройка
(`night.look_max`, по умолчанию 12), — впереди то, без чего осмотр
бессмыслен. Ограждение особое (`sema-осмотр`): по нему Сёма и находит
команды осмотра, а остальной код скилла в осмотр не попадает.

```sema-осмотр
/system resource print
/system package update check-for-updates
/system history print
/user print
/user ssh-keys print
/user active print
/ip service print
/system scheduler print
/system script print
/ip firewall nat print
/interface wireguard peers print
/log print where message~"login failure"
/log print where topics~"error|critical|warning"
/ip dns print
/ip socks print
/interface print
/ip firewall filter print
/ip firewall connection print count-only
/system routerboard print
/system clock print
```

Ниже — то же самое словами: зачем каждая команда и что считать бедой.

### Что проверять

**1. Версия и обновления.**
`/system resource print` — версия, uptime, загрузка CPU, свободная память
и диск. `/system package update check-for-updates`, затем
`/system package update print` — есть ли новая версия (`status: New
version is available`). Пользователю без права `write` роутер отвечает
`not enough permissions` — тогда сравни установленную версию с
опубликованной MikroTik: `sema.http.get('https://upgrade.mikrotik.com/routeros/NEWESTa7.stable')`
отдаёт строку «7.24.2 1788429434» (версия и время); для канала
long-term — `NEWESTa7.long-term`. Версия старше — поле «RouterOS» с
уровнем `warn` и действие `/system package update install` (ждёт
человека). `/system routerboard print` — прошивка (`current-firmware`
против `upgrade-firmware`).

**2. Журнал.** `/log print` без `limit` — RouterOS такого параметра не
знает (`bad parameter limit`); хвост отрежь в коде.
`/log print where topics~"error|critical|warning"` — ошибки;
`/log print where message~"login failure"` — перебор пароля. Смотри
изменения конфигурации (`… changed by …`) и перезагрузки. Много
`login failure` с одного адреса при открытом снаружи `winbox`/`ssh` —
тревога.

**3. Кто изменил конфигурацию.** `/system history print` — список
последних действий, кто и что менял. **Это главная примета на роутере:**
запись об изменении, которого никто не делал, важнее любого счётчика.

**4. Пользователи, ключи и доступ.** `/user print` — список
пользователей: новый или незнакомый — тревога. `/user active print` — кто
подключён сейчас и откуда. `/user ssh-keys print` — **чужие ключи входа**;
ключей стало больше — тревога. `/ip service print` — какие службы открыты
и на каких адресах: `www`, `telnet`, `ftp`, `api` без ограничения
`address` — предупреждение. `/ip ssh print` — настройки ssh.
`/ip cloud print` — включённый MikroTik Cloud с внешним именем даёт
доступ снаружи, знай об этом.

**5. Постоянство: расписания и скрипты.** `/system scheduler print` и
`/system script print` — **этим на MikroTik закрепляются**: чужой скрипт
с `fetch` по адресу в сети и расписанием раз в минуту это классика.
`/file print` — что лежит на роутере; незнакомый файл — вопрос.
`/tool bandwidth-server print`, `/ip socks print`, `/ip proxy print` —
включённый socks или proxy на роутере, которого не заводили, почти всегда
чужой.

**6. Firewall и NAT.** `/ip firewall filter print` — правила;
`/ip firewall nat print` — проброс портов: новая строка `dst-nat`
снаружи внутрь это открытая дверь; `/ip firewall raw print`,
`/ip firewall address-list print`. Сравнивай со вчерашним списком:
исчезнувший `drop` заметнее нового `accept`.
`/ip firewall connection print count-only` — сколько соединений; резкий
рост — возможно, сканирование.

**7. Сеть.** `/interface print` — новый интерфейс, которого вчера не
было (чужой туннель), — тревога. `/ip dns print` — статические серверы
DNS: подмена DNS это тихий и самый частый способ увести трафик.
`/ip address print`, `/ip dhcp-server lease print`.

**8. WireGuard.** `/interface wireguard print` и
`/interface wireguard peers print` — пиры, `last-handshake`; пир без
рукопожатия дольше двух часов отвалился, **новый пир — тревога**.

**9. Здоровье.** `/system health print` — напряжение и температура, если
железо умеет; `/system clock print` — время и NTP: сбитое время ломает
журнал и сертификаты.

### Что считать чем

**Тревога (`alert`).** Новый пользователь или ключ в `/user ssh-keys`;
новое расписание или скрипт; новый пир WireGuard; новое правило `dst-nat`
снаружи; включившийся socks, proxy или `api` без ограничения адреса;
запись в `/system history` об изменении, которого никто не делал; новый
интерфейс.

**Стоит посмотреть (`warn`).** Есть новая версия RouterOS или прошивки;
сотни `login failure` при службе, открытой наружу; отвалившийся пир;
мало памяти или места.

**К сведению (`info`).** Флапы WAN, разовые ошибки в журнале, время
подъехало по NTP.

### Ночная смена: разбор, замена, проба

Роутер с уровнем «полная» Сёма ночью обслуживает сам: осмотр → наряд
работ → каждый шаг через суд двух моделей → проба после шага. Шаг — это
«что, зачем, одна команда, проба, возврат»; без пробы или без возврата шаг
не выполняется, а уходит человеку. На RouterOS это проще, чем на Linux:
почти всё меняется парой `disabled=yes` / `disabled=no`, и возврат
получается точным.

Рамки: одна строка, без `;` и без `[find …]` (скобки читаются как
непонятный синтаксис, и такой возврат страховкой не заведёшь), не дольше
минуты (`ssh.timeout_s`, 60 с). Страховка возврата на роутере —
одноразовое задание `/system scheduler`, которое Сёма ставит до изменения
и снимает сам, когда заново подключился и проба сошлась.

**Что смотреть при разборе команды**

1. **Что это трогает.** `print` — чтение; `set`, `add`, `remove`, `enable`,
   `disable` меняют. `/ip firewall`, `/ip address`, `/ip route`,
   `/interface`, `/user`, `/ip service` — это доступ: правило «Спросить»,
   ночью только со страховкой.
2. **Обратимо ли по номеру или имени.** Возврат должен ссылаться на ту же
   строку; после `remove` номера съезжают, поэтому удаление — плохой
   ночной шаг, а выключение — хороший.
3. **Не потеряется ли связь.** `/system reboot`, `/system package update
   install`, `/system reset-configuration`, смена адреса или правила на
   входном интерфейсе — это разрыв, и ночью его никто не заметит.
4. **Точна ли цель.** Правило, пир, служба — поимённо и по одному.

**Чем заменять опасное**

- `remove` → `set <номер> disabled=yes`, возврат `set <номер> disabled=no`.
  Ненужное удалит человек днём, когда видно, что без этого живётся.
- Правка работающего правила «на живую» → новое правило рядом выключенным,
  затем `disabled=no`; возврат — обратно `disabled=yes`.
- `/system package update install`, `/system routerboard upgrade` и
  `/system reboot` → человеку. В отчёте скажи, что доступна новая версия,
  и назови её, но не ставь: перезагрузка ночью — это связь, которую некому
  вернуть.
- Замена правила одной командой `set … action=…` → два шага: сначала
  выключить старое, потом включить новое, у каждого своя проба.
- `/system scheduler add` и `/system script add` от себя не заводи: этим на
  роутере закрепляется чужой, и твоя запись потом неотличима от его.
  Единственное задание, которое ставит Сёма, — страховка возврата, и он
  снимает её сам.

**Какой пробой проверять**

Проба — любая печать: она разрешена правилами сервера и выполнится сама.

- тронули правило → `/ip firewall filter print` и
  `/ip firewall connection print count-only`;
- тронули службу или доступ → `/ip service print`, `/user active print`;
- тронули интерфейс или адрес → `/interface print`, `/ip address print`;
- тронули WireGuard → `/interface wireguard peers print`:
  `last-handshake` должен обновиться, а не просто существовать;
- тронули расписание или скрипт → `/system scheduler print`,
  `/system script print`;
- общая проба — `/system resource print` (uptime не должен обнулиться:
  обнулился — роутер перезагрузился, а этого никто не просил) и
  `/log print where topics~"error|critical"`.

`/system identity print` пробой не бывает: роутер отвечает на него и когда
всё сломано. Связь Сёма и так проверяет отдельным новым соединением до
пробы.

### Отчёт

Роутер — один из серверов в общем отчёте, отдельной записи ему не
положено: строка в полях общей записи `servers:daily`, подпись — имя
роутера, значение — короткий итог. Норма — `спокойно · RouterOS 7.16.2,
пиров 4 на связи, login failure 0`. Тревога — что именно и цитата строки
журнала или `/system history`, а предлагаемая команда (например
`/system package update install`) идёт **действием записи** и ждёт
подтверждения человека.

### Ответ модели в модуле — JSON

Форма та же, что у скилла «Linux-сервер»: `{"level", "summary", "fields",
"actions"}` — но роутер даёт **одно поле** в общей записи, а не свою
запись. Модулю нужно право `http` для проверки версии на сайте MikroTik.
Журнал в выжимке — не весь `/log print`, а
`/log print where topics~"error|warning|critical|account"` и последние 40
строк.

### В модуле

Роутер осматривается той же задачей, что и Linux-серверы: команды через
`sema.ssh.run('Microtik', '/system resource print')`, выжимка идёт модели
вместе с выжимками остальных серверов одним запросом, а результат — одна
общая `sema.notify({key: 'servers:daily', …})`. Ответ `sema.ssh.run` —
`{output, code}`, а для команды, ждущей человека, `{pending, why}` — это
не ошибка; текст в `r.output`. Вчерашний список правил, пиров,
пользователей и расписаний храни в `sema.store`: без сравнения «новое
правило» не увидеть.
