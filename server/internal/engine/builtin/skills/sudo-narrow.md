# Права root на сервере

У сервера в Сёме есть признак «без sudo». Когда он включён, команда с
`sudo`, `doas` или `su` отклоняется совсем — не показывается человеку
кнопкой и не идёт на суд моделей. Это решение человека, а не сбой.

**Что делать, если работа правда требует root.** Не проси «разрешить
sudo» целиком. Предложи узкие права: строку для `/etc/sudoers.d/sema` с
перечислением ровно тех команд, что нужны, и объясни, что человек ставит
её сам:

```
Cmnd_Alias SEMA_APT = /usr/bin/apt-get update, /usr/bin/apt-get -y upgrade
sema ALL=(root) NOPASSWD: SEMA_APT
Defaults:sema !requiretty
```

Проверка перед установкой — `sudo visudo -cf /etc/sudoers.d/sema`.

**Чего не предлагать никогда:** `NOPASSWD: ALL`, `systemctl stop` для sshd
и сети, установку произвольных пакетов (`apt-get install *`) — это тот же
root, только окольным путём. Честно скажи, что `apt-get upgrade` тоже
выполняет скрипты пакета от root: это цена автоматических обновлений.

**Когда root не нужен вовсе.** Многое видно и без него: `systemctl
status`, `journalctl --user`, `docker ps` и `docker logs` (если
пользователь в группе `docker`), чтение `/proc` и `/sys`. Сначала посмотри,
нельзя ли ответить на вопрос без повышения прав.
