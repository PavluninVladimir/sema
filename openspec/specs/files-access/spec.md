# files-access Specification

## Purpose
Файл получают только через сервер: клиент и модули не знают путей и
хранилищ. Так Сёма одинаково работает на маке, в Docker и на Pi.
## Requirements
### Requirement: Получение файла через сервер

Сервер SHALL отдавать содержимое файла по его id с правильным типом, доставая
его из того хранилища, где файл лежит. Клиент SHALL открывать файлы через
эту ручку, а не по пути на диске сервера.

#### Scenario: Сервер в Docker

- **WHEN** человек нажимает «Открыть» у файла, а сервер работает в контейнере
- **THEN** файл открывается системным приложением на маке

### Requirement: Загрузка файла

Сервер SHALL принимать файл загрузкой, считать хэш, класть в основное
хранилище, записывать источник «загрузка» и сообщать модулям о новом файле.
Клиент SHALL позволять перетащить файл в окно Сёмы.

#### Scenario: Перетащили счёт

- **WHEN** человек перетащил PDF со счётом в окно
- **THEN** файл появляется в «Файлах» с источником «загрузка», а модуль
  «Чеки» заводит чек

### Requirement: Карточка файла

У файла SHALL быть карточка: имя, тип, размер, источники, расположение,
извлечённый текст, разобранные модулями поля; действия «Открыть», «Письмо»
(если есть), «Удалить» с перечислением источников.

#### Scenario: Удаление файла с двумя источниками

- **WHEN** человек удаляет файл, пришедший из письма и загрузкой
- **THEN** подтверждение перечисляет оба источника, после удаления файла нет,
  письмо и его текст остаются

### Requirement: Файл в чат

Человек SHALL уметь перетащить файл на экран чата: файл сохраняется с
источником «загрузка · чат», в переписке появляется сообщение с чипом
файла, а файл попадает в контекст ответа этого чата.

#### Scenario: Спросить про документ

- **WHEN** человек перетащил договор в чат и спросил «что здесь про сроки»
- **THEN** в переписке сообщение с чипом договора, ответ опирается на его
  текст, чип открывает файл
