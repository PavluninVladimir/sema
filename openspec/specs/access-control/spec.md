# access-control Specification

## Purpose
Вход в Сёму: человек — по passkey, программы — по токенам, и всё это
видно и отзывается.
## Requirements
### Requirement: Вход по passkey

Сёма SHALL пускать человека по passkey (WebAuthn); ключей может быть
несколько. Первый ключ SHALL регистрироваться только с самой машины
(localhost) или из открытой сессии. Пока ни одного ключа нет, запросы с
localhost SHALL считаться вошедшими, а с сети — отклоняться.

#### Scenario: Вход с телефона по сети

- **WHEN** человек открывает Сёму по адресу Pi без сессии
- **THEN** видит экран входа, проходит passkey через Bitwarden и попадает в
  Сёму; без ключа запросы получают 401

### Requirement: Сессии видны и отзываются

Открытые сессии SHALL быть списком на экране «Доступ» с устройством и
временем; каждую SHALL можно завершить, и «Выйти везде» SHALL завершать все.

#### Scenario: Потерянный ноутбук

- **WHEN** человек нажимает «Выйти» у сессии ноутбука
- **THEN** ноутбук на следующем запросе получает экран входа

### Requirement: Токены для API с правами и журналом

Токен SHALL выдаваться с названием и правами (экраны, действия, файлы,
память), показываться один раз, храниться хэшем и отзываться. Каждый
запрос с токеном SHALL писаться в журнал доступа, статистика по токену
SHALL быть на экране «Доступ» и на «Здоровье» как расход потребителя.

#### Scenario: Токен для Claude Code

- **WHEN** человек выдал токен «claude-code» с правом «память»
- **THEN** MCP и хуки работают с ним, в журнале видны запросы по дням, а
  запрос экрана с этим токеном получает 403

#### Scenario: Отозвали

- **WHEN** токен отозван
- **THEN** следующий запрос с ним получает 401 и попадает в журнал как отказ
