## Context

Telegram и MAX работают через пользовательские сессии. Каналы уведомлений могут обращаться к ботам через конфигурацию модулей и выданные им секреты.

## Goals / Non-Goals

Первый выпуск управляет подключениями. Получение обновлений, отправка сообщений и привязка к сценариям выполняются отдельными изменениями.

## Decisions

- Добавить `settings:bots` в общий каркас рядом с Telegram и MAX. Для группы «Каналы» допустимы семь пунктов. Применить штатные вкладки и страницы сущностей. Старые адреса Telegram и MAX продолжают открывать личные подключения.
- Хранить несколько ботов с локальным идентификатором и уникальной парой «платформа, внешний идентификатор». У каждого бота собственный служебный секрет в существующем хранилище. Общая транзакция сохраняет и удаляет связанные записи. Повторная проверка сохраняет только статус своей версии токена.
- Ограничить операции чтением `getMe` у Telegram и `GET /me` у MAX с заголовком `Authorization`. Использовать HTTPS с проверкой доверия, фиксированные адреса платформ, срок запроса и запрет перенаправлений. Состояние возвращается из фиксированного набора, чтобы ошибки запроса Telegram не раскрыли токен из URL.
- При замене получать сведения новым токеном до записи и сверять идентификатор. Отключение удаляет только локальные данные.

## Risks / Trade-offs

- Сертификат платформы MAX должен быть доверен средой запуска. Ошибка TLS показывается как ошибка связи.
- Проверка сохранённого токена и его замена могут выполняться одновременно. Запись результата проверки сравнивает версию токена, прочитанную перед сетевым вызовом.

## Migration Plan

Создать таблицу подключений при старте. Пользовательские сессии, правила пересылки и секреты модулей не мигрируют.
