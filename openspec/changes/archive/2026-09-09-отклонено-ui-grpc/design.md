## Context

См. `proposal.md` — Why. Здесь только то, что определяет форму решения.

**Как приложение получает экраны сегодня.** `SemaAPI.fetchUI` —
`GET /api/ui?screen=…` с `If-None-Match`, ответ JSON `UIDocument`; действие
— `POST /api/action` с JSON, ответ — документ. `SemaApp.swift` держит два
таймера: `autoRefresh` раз в 5 с и `liveRefresh` раз в 0,3 с, пока Сёма
пишет. Сессия — `Bearer sema_s_…` в заголовке, получается по одноразовому
коду через `/login` в браузере и `/api/auth/claim`.

**Словарь.** `api/ui.go` — `Document`, `Component` (около сорока
необязательных полей, из которых каждый тип компонента использует свой
десяток), `Field`, `Action`, `Select`, `Badge`, `Prop`. Версия словаря —
`UIDictVersion`/`uiDictMin`, заголовок `X-Sema-UI`, экран «Обновите клиент»
при несовместимости. Клиент повторяет структуры в `Model.swift` как
`Codable` и рисует в `DynamicView.swift`, не зная предметной области.

**Что уже есть на сервере.** Узел сигналов `engine/live.go`: подписка
даёт кадры с именами изменившихся экранов, склейка окном `ui.live_ms`.
HTTPS на 8443 с сертификатом, которому мак доверяет (mkcert).

**Приложение.** SwiftPM, macOS 14, без внешних зависимостей. На маке есть
`protoc`; `protoc-gen-swift` и `protoc-gen-grpc-swift` ставятся из
`swift-protobuf` и `grpc-swift`.

## Goals / Non-Goals

**Goals:**

- Экран в приложении обновляется по изменению, а не по таймеру; ответ Сёмы
  появляется по мере написания без опроса раз в 0,3 с.
- Форма экрана записана один раз и проверяется компилятором с обеих
  сторон; новое поле — правка в одном файле и перегенерация.
- Ни одна дверь безопасности не открывается: тот же вход, та же сессия, те
  же права токенов.

**Non-Goals:**

- Веб-клиент: он на разметке `/ui` и живом проводе, ему gRPC не нужен.
- Файлы (`/api/files`), пуши, вход (`/login`, `/api/auth/*`), здоровье —
  остаются HTTP: это либо байты, либо браузер.
- Модули с экранами: они отдают документы через ядро, ядро переводит;
  манифесты модулей не меняются.

## Decisions

### 1. Поток экранов поверх узла сигналов, а не свой опрос на сервере

`Screen(ScreenRequest) returns (stream Document)`: сервер отдаёт документ
сразу, потом подписывается на узел сигналов и присылает новый документ,
когда в кадре есть имя этого экрана (с тем же правилом «`inbox` относится
к `inbox@ящик`», что у веб-клиента). Пока Сёма пишет ответ, частичный
текст сигналит чат, и документы идут не чаще окна склейки — те же 300 мс,
что стояли у `liveRefresh`. Смена экрана в приложении — новый вызов
`Screen`, старый поток отменяется.

Альтернатива — унарный `Screen` плюс отдельный поток сигналов «перечитай»
(как у веба) — отвергнута: у приложения нет причины делать два запроса,
когда сервер и так собирает документ по сигналу; лишний круг только
добавляет задержку.

ETag не нужен: документ уходит только по сигналу. Но сервер SHALL не
слать документ, если он совпал с прошлым байт в байт, — иначе кадр
`chats` при каждой заметке перерисует список без изменений.

### 2. Словарь — сообщения protobuf, версия — контрактом

`Component` переезжает как одно сообщение с необязательными полями
(proto3 `optional` даёт присутствие, как `omitempty`): форма у сервера и
клиента одна, и `DynamicView.swift` читает те же имена. Разбивать на
`oneof` по типу компонента отвергнуто: сегодня строка списка, карточка и
пузырь чата делят поля, а сервер собирает их в одном месте — расщепление
удвоило бы код сборки экранов ради красоты схемы.

Совместимость: неизвестные поля protobuf пропускает сам, поэтому
`UIDictVersion` (новое поле, которое старый клиент может пропустить)
больше не нужен. `uiDictMin` остаётся как поле метаданных `x-sema-ui-min`:
изменение смысла поля, при котором старый клиент нарисует неправду,
по-прежнему требует руки человека, и клиент со старым номером получает
экран «Обновите клиент» тем же документом.

`web/dictionary.txt` и `app/dictionary.txt` (договор типов) остаются:
тест `dictionary_test.go` проверяет типы компонентов, а не транспорт.

### 3. Тот же порт 8443, разбор по типу содержимого

Сервер gRPC подключается к нынешнему HTTPS: запрос с `Content-Type:
application/grpc` по HTTP/2 уходит в `grpcServer.ServeHTTP`, остальное —
в обычный маршрутизатор. Один порт, один сертификат, одна настройка
`SEMA_TLS_LISTEN`. Приложение уже доверяет этому сертификату.

Отдельный порт отвергнут: ещё одно число в `docker run`, в документации
и в голове; выигрыша нет.

### 4. Сессия — в метаданных, права — те же

`authorization: Bearer sema_s_…` в метаданных вызова; перехватчик зовёт
тот же `Identify`, что и `protect`, и тот же `mayAdmin` для действий
доступа. Токен с правом «экраны» может `Screen`, с правом «действия» —
`Act`; `ScopeFor` получает имена методов рядом с путями. Локальный запрос
без входа (`auth.local_open`) действует и здесь — адрес берётся из
`peer.FromContext`.

### 5. Действия — унарный `Act`, тот же диспетчер

`Act(ActionRequest) returns (Document)` зовёт `execute` и `buildScreen`,
как `handleAction`. Клиентские действия `$…` остаются на клиенте.
Подтверждения (`Confirm`, `ConfirmOK`) — поля компонента, как сейчас.

### 6. Приложение: один поток на экран, таймеры уходят

`AppState` держит одну задачу `Screen`; смена экрана отменяет её и
открывает новую. Обрыв потока — переподключение с растущей паузой и
сбросом после живой связи (тот же урок, что у агента и у веба); пока
потока нет — экран показывает последнее полученное с плашкой «нет
связи», а не заглушку. Таймеры `autoRefresh` и `liveRefresh` удаляются.

Библиотека — `grpc-swift` 1.x (SwiftNIO): она поддерживает macOS 14, а
вторая версия требует macOS 15. Сгенерированный код (`swift-protobuf`,
`grpc-swift`) коммитится.

### 7. Переезд — сначала поток рядом с JSON, JSON-действия снимаются последними

Порядок: контракт → сервер с обеими дорогами → приложение на gRPC →
проверка на живом → `/api/action` снимается, `/api/ui` остаётся
диагностической ручкой (`curl … | python3 -m json.tool` в `CLAUDE.md` и
`screens_test.go` ей пользуются). Откат до последнего шага — старая
сборка приложения.

## Risks / Trade-offs

**Сорок необязательных полей в одном сообщении.** Схема получится
широкой. → Это честный портрет сегодняшнего словаря; расщепление — своё
изменение, когда словарь устоится.

**Первая внешняя зависимость у приложения.** До сих пор `Package.swift`
без зависимостей, сборка `bundle.sh` быстрая. → SwiftNIO и grpc-swift
прибавят минуты к чистой сборке; названо в задачах, замеряется.

**HTTP/2 и прокси.** На Pi приложение ходит напрямую по 8443; за чужим
прокси HTTP/2 может не пройти. → Диагностика в приложении говорит словами
«поток не открылся», а не молчит; веб-клиент остаётся запасным входом.

**Часть экранов рисуется модулями.** Их документы идут через тот же
перевод в сообщения; неизвестный тип компонента и сегодня ловит
`dictionary_test.go`.
