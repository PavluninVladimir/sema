## Context

Настройки ящика (`store.MailConf`) уже индивидуальны: авторизация, папки,
архив, спам, глубина, список задач. Воркеры почты — общие строки задач,
которые обходят все ящики. Облачность модели ядро уже различает
(`ModelIsCloud`) для областей памяти. Нужен режим ящика, который воркеры
уважают, и признак «наружу», который контекст чата уважает.

## Goals / Non-Goals

**Goals:**

- Рабочую почту можно подключить так, что на сервере не меняется ничего.
- Рабочая переписка не уходит облачной модели, пока человек не откроет.
- Список задач ящика не даёт включить то, что режим запрещает.

**Non-Goals:**

- Отдельные учётные записи или права доступа внутри Сёмы.
- Раздельные базы для личного и рабочего.

## Decisions

### Режим — поле ящика, которое проверяют воркеры, а не набор задач

`MailConf.Mode` ∈ `tidy` | `readonly`. Воркеры `folders` и `purge` пропускают
ящики `readonly`; `poll` для них не вызывает фильтр, не переносит и не
помечает прочитанным, письма получают статус «проверено» сразу. Список
задач в карточке ящика показывает недоступные строки серыми и не даёт
включить — так ошибка невозможна физически, а не по договорённости.

*Альтернатива:* режим как пресет галочек задач — отклонено: пресет можно
разобрать руками, и одна оставшаяся задача сделает вред.

### «Наружу» ящика — фильтр в сборке контекста

`MailConf.Outbound bool`; по умолчанию `true` для личного, `false` для
рабочего (назначение задаётся при добавлении, менять можно). В
`chatPrompt` при облачной модели `ragContext`, `receiptsDigest` и файлы по
имени исключают сообщения закрытых ящиков (`messages.account`), а в промпт
идёт строка «ящики X закрыты для этой модели». Задачи, идущие через облачную
модель (пользовательские с промптом), получают тот же контекст.

### Галочки сбора — булевы поля с умолчаниями по назначению

`CollectReceipts` (личная — вкл, рабочая — выкл), `CollectAttention` (везде
вкл). `receiptPass` пропускает письма ящиков без галочки; извлечение
«требует внимания» (из изменения `mail-digest`) читает свою галочку и не
зависит от режима.

### Экран — переключатели сверху карточки ящика

Первая строка карточки: «Назначение» и «Режим» сегментами, под ними галочки
«чеки и счета», «требует внимания» и тумблер «отдавать облачной модели».
Существующий блок задач остаётся, но строки, невозможные в режиме, серые с
подписью.

## Risks / Trade-offs

- **Смена режима на «только читать» не откатывает уже сделанное** — письма,
  перенесённые раньше, остаются где лежат. На экране об этом сказано.
- **Закрытый ящик делает облачный чат «слепым» к части почты**, и человек
  может решить, что Сёма не нашёл письмо. Смягчение: ответ прямо называет
  закрытый ящик.
