## Why

Сёма слушает только 127.0.0.1 на маке, и это единственная защита: любой
процесс на машине читает всю почту, файлы, память и секреты. Перед
переездом на Raspberry Pi, где Сёма будет доступна по сети, нужен вход:
человек — по passkey (Bitwarden), внешние программы и агенты — по токенам с
журналом и статистикой. Без этого на Pi ехать нельзя.

## What Changes

- **Вход по passkey (WebAuthn).** Первый passkey регистрируется с мастера
  первого запуска или с экрана «Доступ» при входе с localhost; дальше
  вход — прикоснуться к ключу в Bitwarden. Сессия — cookie на 30 дней,
  продлевается при использовании; список сессий с выходом. Пока passkey не
  зарегистрирован, вход с localhost открыт (как сейчас), с сети — закрыт.
- **Токены для API.** Экран «Доступ»: выдать токен с названием и правами
  (чтение экранов, действия, файлы, память по MCP), увидеть его один раз,
  отозвать. Каждый запрос с токеном пишется в журнал: кто, что, когда,
  сколько; статистика по токену за день, неделю, месяц там же и на
  «Здоровье» как потребитель `token:<имя>`.
- **Кто и как заходит.** Клиент на маке — passkey через системное окно
  (Bitwarden как провайдер), хуки Claude Code и MCP — токен в заголовке
  `Authorization: Bearer`, скрипты `integrations/` получают токен из
  переменной окружения.
- **Домен.** WebAuthn требует RP ID: на маке `localhost`, на Pi — имя из
  Tailscale (`sema.tail…ts.net`) из настроек; смена имени не ломает старые
  ключи только при одинаковом RP ID, поэтому имя задаётся один раз в
  мастере переезда (`pi-deploy`).

## Capabilities

### New Capabilities

- `access-control`: passkey, сессии, токены, журнал доступа, экран «Доступ».

### Modified Capabilities

- `mcp-access`: MCP и хуки ходят с токеном.
- `dynamic-ui`: экран входа и мастер регистрации passkey в клиенте.

## Impact

- `internal/auth`: WebAuthn (go-webauthn/webauthn, чистый Go), сессии,
  токены (хэш в базе, значение показывается один раз), middleware.
- `store`: `passkeys`, `sessions`, `api_tokens`, `access_log`.
- `api`: `/api/auth/*`, middleware на всё остальное, экран `access`.
- Клиент: экран входа с кнопкой «Войти с passkey» (ASAuthorization),
  cookie в URLSession, регистрация ключа.
- `integrations/`: токен в хуках и MCP-конфиге.
