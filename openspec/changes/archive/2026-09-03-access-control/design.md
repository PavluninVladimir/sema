## Context

Сервер без аутентификации, слушает 127.0.0.1 (в Docker 0.0.0.0 внутри
контейнера, наружу проброшен только localhost). Клиент — SwiftUI на маке,
API — JSON поверх HTTP, MCP на `/mcp`, хуки на `/api/memory/session_*`.
Секреты шифруются `SEMA_KEY`. Журнал расхода уже умеет потребителей.

## Goals / Non-Goals

**Goals:**

- С сети в Сёму не войти без passkey; внешние программы — только с токеном.
- Каждый вход и каждый запрос по токену виден человеку.
- Локальная работа на маке не усложняется, пока ключ не заведён.

**Non-Goals:**

- Несколько пользователей и роли между ними: Сёма личная.
- Пароли как способ входа: только passkey и токены.
- TLS в самой Сёме: его даёт Caddy/Tailscale (`pi-deploy`).

## Decisions

### Passkey через go-webauthn, RP ID из настроек

`go-webauthn/webauthn` — чистый Go. RP ID и origin — настройки
(`auth.rp_id`, `auth.origin`), по умолчанию `localhost` и
`http://localhost:8765`. Регистрация первого ключа разрешена только с
localhost или из открытой сессии; дальше — только из сессии. Ключей может
быть несколько (мак, телефон). Bitwarden выступает провайдером passkey на
стороне клиента, серверу всё равно.

### Сессии — cookie, не JWT

`sessions(id, passkey_id, created, last_seen, ua, ip)`; cookie `sema_session`,
HttpOnly, 30 дней, продление при запросе. Список на экране «Доступ» с
кнопкой «Выйти» у каждой и «Выйти везде».

### Токены — хэш в базе, права списком

`api_tokens(id, name, hash, scopes, created, last_used, revoked)`. Значение
`sema_<32 байта base64url>` показывается один раз. Права: `ui` (экраны),
`actions`, `files`, `memory` (MCP и хуки), `all`. Проверка в middleware:
`Authorization: Bearer` → токен → права против маршрута. Каждый запрос —
`access_log(token_id, at, method, path, status, bytes)`, статистика
агрегируется; потребитель расхода `token:<имя>`, если запрос вызвал модель.

### Открыто без входа

`GET /api/health`, `/api/auth/*` (начало входа, регистрация первого ключа с
localhost), всё остальное — сессия или токен. Пока ни одного passkey нет,
запросы с loopback считаются вошедшими: мак работает как раньше.

### Клиент

Экран входа: «Войти с passkey» через `ASAuthorizationPlatformPublicKeyCredentialProvider`
(macOS 13+), Bitwarden подхватывает системный диалог. Cookie хранит
`URLSession`. Первый запуск на Pi: мастер предлагает завести ключ.

## Risks / Trade-offs

- **RP ID и смена домена**: ключи, заведённые под `localhost`, не подойдут
  для `sema.tail….ts.net`. При переезде заводится новый ключ, старые
  остаются для локального входа — экран это объясняет.
- **Потеря всех ключей** — вход с localhost на самой машине остаётся
  запасным путём: `sema-server -reset-auth` печатает одноразовую ссылку.
