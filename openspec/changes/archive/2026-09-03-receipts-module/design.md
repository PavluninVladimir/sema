## Context

Чеки в ядре: воркер `receiptPass` (тело письма), `analyzeReceipt` (вложение),
таблица `receipts` со связью с письмом, категории и слова-приметы в
`categories`, окно склейки в настройках, `receiptsDigest` в промпте чата,
`sema.receipts` в песочнице, сумма в группе дайджеста и бейдж у файла.
Среда модулей уже даёт всё нужное: события с текстом письма и файла,
коллекции с суммой в SQL, `sema.llm` с локальной моделью для закрытых
ящиков, экраны с формами, контекст и инструменты модулей.

## Goals / Non-Goals

**Goals:**

- Ядро не знает, что такое чек. Всё про деньги — модуль, который можно
  выключить, скопировать и переписать.
- Ни одна разобранная сумма не теряется при переезде.
- Дайджест и файлы показывают суммы так же, как сейчас.

**Non-Goals:**

- Новые источники чеков (банковские выгрузки, фото из галереи).
- Бюджеты и лимиты трат.

## Decisions

### Модуль `receipts`: события, а не воркер

`on: message, attachment`. Обработчик письма: дешёвый фильтр (денежные
слова и сумма — списки в коллекции `settings`, правятся с экрана) →
`sema.llm` с промптом извлечения → документ в `receipts`: {msg, file,
vendor, amount, currency, summary, category, date, account, source}.
Обработчик файла: то же по тексту вложения; документ помечается
`source: "attachment"`, файл — через `sema.files.mark(id, {kind:
"receipt", vendor, amount, currency})` — единственная новая ручка ядра,
нужна для бейджа в «Файлах» и поиска по виду файла.

*Альтернатива:* оставить воркер в ядре и звать модуль из него — отклонено:
тогда ядро всё ещё знает про чеки.

### Категории и склейка — данные модуля

`categories` {title, keywords[], suggested, sort}; `settings/merge`
{days}. Категория назначается при извлечении по приметам, неизвестному
получателю модуль предлагает категорию с пометкой «предложила Сёма». Склейка
«счёт и оплата» — при выдаче сумм, как сейчас.

### Ядро спрашивает модуль, а не наоборот

`Engine.CallModuleTool(name, fn, args)` — вызов инструмента модуля из Go с
таймаутом 5 с. Дайджест зовёт `receipts.forMessages(ids)` и получает суммы
по письмам; «Файлы» — то же для бейджей; опись (`inventory.go`) —
`receipts.count()`. Нет модуля или он выключен — ответ пустой, экраны не
ломаются, группа «Счета и чеки» остаётся по словам в теме.

### Переезд данных — в модуле, при первом включении

Функция `migrate()` модуля читает старые таблицы через временный
инструмент ядра `sema.legacy.receipts()` / `sema.legacy.categories()`,
кладёт их в свои коллекции и ставит отметку в `settings/migrated`. После
этого ядро удаляет таблицы `receipts`, `categories` и настройку окна
склейки следующей миграцией (в этом изменении — только после подтверждения
на живой системе, что суммы сходятся).

### Экран «Чеки» модуля

Сверху период сегментами (месяц, прошлый месяц, год) и сумма по
категориям; список чеков с получателем, суммой, категорией и источником
(письмо/файл); категории с приметами и формой добавления; настройки:
слова-приметы денег, окно склейки. Всё — `module_action` в функции модуля.

## Risks / Trade-offs

- **Модель в модуле дороже воркера с дешёвым фильтром?** Нет: фильтр
  остался, просто он теперь данные модуля.
- **Вызов модуля при каждой сборке дайджеста** — 5-секундный таймаут и
  один вызов на экран; коллекции считаются в SQL.
- **Старые чеки без категории после переезда** — переносятся как есть,
  категория по приметам пересчитывается при первом показе.
