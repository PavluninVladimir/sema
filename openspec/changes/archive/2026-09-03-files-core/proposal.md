## Why

Файл в Сёме — это вложение письма: запись жёстко привязана к письму, путь
на диске сервера уходит клиенту как есть, а событие «файл» означает
«вложение». Отсюда три беды: файл без письма (перетащили, скан из папки,
принёс модуль) положить некуда; «Открыть» не работает, когда сервер в Docker
или на Pi, потому что путь чужой; модуль «Чеки» привязан к почте, хотя чек
— это файл, откуда бы он ни пришёл. Плюс события модулей разбираются раз в
десять секунд, а должны — сразу.

## What Changes

- **Файл — самостоятельная сущность.** Таблица `files`: хэш содержимого,
  имя, тип, размер, текст, вид, **источник** (письмо с ящиком, загрузка,
  папка, модуль) и **расположение** (какое хранилище, ключ). Письмо —
  необязательная ссылка. Один и тот же файл из двух источников — одна
  запись с двумя источниками.
- **Хранилища — справочник, а не папка в коде.** Сейчас реализуется
  локальное (`/data/files/<хэш>`), интерфейс готов под S3-совместимое
  (адрес, bucket, ключи из хранилища секретов) — оно придёт отдельным
  изменением `files-s3`. На экране «Хранилища» видно, что где лежит и
  сколько занимает.
- **Байты файла отдаёт сервер.** `GET /api/files/<id>` и `POST /api/files`
  (загрузка). Клиент открывает файл через сервер, а не по пути; в карточке
  файла видны источник, расположение и извлечённый текст. Первый неписьменный
  источник — перетаскивание в окно клиента.
- **Общий словарь событий и мгновенная доставка.** `file.added`,
  `file.changed`, `message.added`; старые `attachment` и `message` —
  синонимы. `emit` будит разборщик сразу, очередь остаётся ради повторов.
- **Модули получают источник.** Обработчик файла видит `f.source` и
  `f.location`; «Чеки» подписывается на файлы откуда угодно, письмо для чека
  необязательно; «Требует внимания» — на письма и файлы.
- **Переезд старых вложений** — фоновой задачей с прогрессом: хэш,
  источник «письмо», расположение «локально».

## Capabilities

### New Capabilities

- `files-storage`: файл как сущность с источником и расположением;
  справочник хранилищ, локальное хранилище по хэшу, дедупликация.
- `files-access`: получение и загрузка файлов через сервер, карточка файла.
- `module-events`: общий словарь событий ядра, синонимы, мгновенная доставка.

### Modified Capabilities

- `files-extraction`: извлечение текста работает для файла любого
  источника; повторное извлечение — событие `file.changed`.
- `receipts-categories`: чек привязан к файлу, письмо необязательно.
- `attention`: события по новому словарю.

## Impact

- `store`: таблица `files` (заменяет `attachments`), `file_sources`,
  `storages`; миграция данных фоновой задачей.
- `engine/files.go`, `extract.go`, `tools.go`: работа с файлом по id и
  хранилищу; `engine/storage/` — интерфейс и локальная реализация.
- `api`: `/api/files/<id>`, `/api/files` (POST), экран «Файлы» с
  капсулами источника и хранилища, карточка файла, экран «Хранилища».
- Клиент: открытие файла через сервер (временный файл), перетаскивание в
  окно — одно новое действие `$file`.
- `module_platform.go`: словарь событий, синонимы, будильник разборщика.
- `builtin/receipts.js`, `builtin/attention.js`: новые имена событий и
  поля источника.
