## Context

`attachments(message_id NOT NULL, path, extracted, kind, vendor, amount…)`,
файлы лежат в `files/<id письма>_<имя>` на диске сервера; клиенту уходит
`$open <путь>`. События ядра — `message` и `attachment`, разбор очереди
`module_events` раз в 10 секунд. Хранилище секретов и справочники с экранами
уже есть; модули получают события с текстом файла.

## Goals / Non-Goals

**Goals:**

- У файла всегда известны источник и расположение, и это видно человеку.
- Файл получают только через сервер: клиент и модули не знают, где он лежит.
- Файл может прийти не из почты, и модули узнают об этом сразу.
- Хранилище меняется настройкой; локальное — сейчас, S3 — следующим шагом.

**Non-Goals:**

- Сама реализация S3 (отдельное изменение `files-s3`).
- Слежение за папкой на диске и `sema.files.add` для модулей — после
  загрузки через сервер, тем же путём.
- Просмотрщик PDF внутри клиента: открываем системным приложением.

## Decisions

### Файл — запись, а не путь; хранение по хэшу

`files(id, sha256 UNIQUE, name, mime, size, text, kind, vendor, amount,
currency, summary, storage, key, created)`; `file_sources(file_id, source,
ref, account, added)` — источников у файла может быть несколько
(`mail:<message_id>`, `upload`, `folder:<путь>`, `module:<имя>`). Ключ в
хранилище — `ab/cd/<sha256>`: одинаковое содержимое кладётся один раз, второй
источник только дописывается. Имя файла и текст — у записи, не у ключа.

*Альтернатива:* оставить `attachments` и добавить `message_id NULL` —
отклонено: дедупликации нет, путь остаётся публичным.

### Хранилища — справочник с интерфейсом

`storages(name, kind, config json, primary, quota)`; интерфейс
`storage.Backend{Put(key, r) ; Get(key) ; Delete(key) ; Stat()}`. В этом
изменении — `local` (корень из настройки, по умолчанию `<data>/files`).
Основное хранилище одно; смена основного переносит файлы фоновой задачей.
Ключи S3 — в хранилище секретов, в `config` только их имена.

### Байты — только через сервер

`GET /api/files/<id>` отдаёт содержимое с правильным `Content-Type`,
`POST /api/files` (multipart) принимает файл, считает хэш, кладёт в основное
хранилище, пишет источник `upload` и эмитит `file.added`. Клиент по действию
`$file <id>` скачивает во временную папку и открывает системным приложением;
`$open` с путём остаётся для локальных инструментов (журнал, файл запуска).

### Словарь событий и синонимы

`EventKinds`: `message.added`, `file.added`, `file.changed`. Манифест может
писать старые `message`/`attachment` — при разборе они превращаются в новые,
права (`GrantedEvents`) переезжают миграцией. `file.changed` эмитится, когда
у файла заново извлечён текст (появился OCR, перечитали) или пришёл тот же
хэш имени с другим содержимым из того же источника.

### Мгновенная доставка

`emitModuleEvent` после записи в очередь дёргает канал разборщика; задача
«События модулей» остаётся страховкой (раз в 10 секунд) и местом для
повторов. Разбор идёт по-прежнему по одному событию за раз на модуль.

### Payload файла

`{id, name, mime, kind, text, sha, source: {kind, ref, account}, location:
{storage, key}, message: {…} | null, local, collect}`. `local` и `collect`
считаются по ящику источника; у файла без письма `local` — по умолчанию
хранилища секретов? Нет: `local=false`, `collect` — все включены. Модуль
видит это и решает сам.

### Переезд

Задача «Переезд файлов» (одноразовая, с прогрессом): для каждой строки
`attachments` — хэш файла с диска, запись в `files` и `file_sources`
(`mail:<message_id>`, ящик из письма), перенос файла под ключ по хэшу,
`kind/vendor/amount` переносятся как есть. Пока задача идёт, экран «Файлы»
читает обе таблицы; по окончании `attachments` удаляется следующей миграцией.

## Risks / Trade-offs

- **Один файл — несколько источников** усложняет «Удалить»: удаляем файл,
  когда сняли последний источник; в UI «Удалить» удаляет файл целиком с
  подтверждением, в котором перечислены источники.
- **Загрузка больших файлов** через API — предел из настроек (как
  `FilesMaxMB`), сервер отвечает понятной ошибкой.
- **Открытие через временный файл** медленнее прямого пути на маке —
  приемлемо: путь всё равно чужой, когда сервер не на маке.
