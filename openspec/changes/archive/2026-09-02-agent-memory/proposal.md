## Why

Сёма не помнит ничего между разговорами. Сегодня он разобрал с человеком счета за
месяц и выяснил, что одна строка счёта двоится; завтра в новом чате
он соберёт те же 4 000 токенов контекста (опись, выписка чеков, письма) и
снова удвоит ту же строку. Те же деньги жгут Claude Code и Codex на этой машине:
каждая новая сессия заново читает CLAUDE.md, ищет по репозиторию и теряет
после сжатия контекста то, что уже выяснила.

Цель — экономить токены: и у Сёмы, и у локальных агентов, которыми владелец
работает на компьютере. Память нужна одна на всех — урок, выученный Claude
Code в проекте, должен быть виден Codex и Сёме; а границы доступа и правила
(guardrails) должны настраиваться, а не быть зашитыми. Ориентир по модели
записей — agentmemory (наблюдения → факты → уроки → кристаллы → граф), но
память живёт в Сёме: Go, SQLite, без Node и внешних сервисов, чтобы работать
и на Raspberry Pi.

## What Changes

- Единая память Сёмы: факты с цепочкой версий, уроки (правила, закрепившиеся
  повторением), кристаллы (сводки сессий), наблюдения (сырые события, живут
  недолго) и граф сущностей со связями. На каждой записи происхождение:
  сессия, агент, модель, область.
- Области памяти как метки доступа, а не отдельные хранилища: справочник в
  базе, первичный набор при первом запуске, Сёма может предложить новую —
  заводит человек.
- Guardrails на входе (маски секретов, области «не запоминать», режим
  подтверждения по области, размер записи) и на выходе (область не выдана —
  отказ и журнал; облачной модели только области с флагом «можно наружу»;
  лимиты на промпт; срок жизни эпизодов). Всё правится на экране «Память».
- Журнал обращений к памяти: кто, когда, из какой области, сколько токенов
  ушло — экономия видна цифрами.
- Сёма-чат читает память вместо повторного поиска по письмам и пишет в неё
  по правилам области; модули просят области в манифесте и получают
  примитив в песочнице; внешние агенты (Claude Code, Codex) подключаются по
  MCP с выданным набором областей, с хуками на начало и конец сессии.
- Консолидация локальной моделью роли «Память»: слияние дублей от разных
  агентов в одну запись с несколькими источниками, закрепление уроков,
  устаревание и сжатие эпизодов.
- Экран «Память» и строки областей на экране установки модуля — макеты до
  кода.

## Capabilities

### New Capabilities

- `agent-memory`: единая память с происхождением, видами записей и графом;
  области и guardrails; журнал; консолидация.
- `mcp-access`: Сёма как MCP-сервер для внешних агентов с выданными
  областями памяти; хуки сессии для Claude Code и Codex; фильтр секретов на
  входе.

### Modified Capabilities

- `modules`: поле `memory` в манифесте, выдача областей поимённо при
  установке и с экрана «Память», примитив памяти в песочнице.
- `assistant-chat`: контекст ответа берётся из памяти раньше повторного
  поиска по письмам; что и куда уходит, зависит от модели (облачная видит
  только открытые области); Сёма предлагает запомнить факт или урок.
- `models-and-tools`: новая роль «Память» для извлечения фактов, графа и
  консолидации, по умолчанию локальная модель.

## Impact

- `server/internal/store`: таблицы `memories`, `memory_versions`, `nodes`,
  `edges`, `sessions`, `memory_areas`, `memory_rules`, `memory_log`;
  FTS5 (есть в modernc.org/sqlite) и векторы через существующий `embed`.
- `server/internal/engine`: `memory.go` (запись, поиск BM25 + вектор + граф,
  guardrails), `memory_consolidate.go`, роль `RoleMemory`, правки `chat.go`
  (память в контекст, фильтр по модели), `modules.go` (`memory` в манифесте,
  `Granted` областей), `scripts.go` (`sema.memory.*`).
- `server/internal/mcp` (новый): MCP-сервер поверх stdio/HTTP, инструменты
  `memory.recall`, `memory.remember`, `memory.session_start/end`; примеры
  хуков для Claude Code и Codex.
- `server/internal/api`: экран `memory` и `memory@<область>`, строки
  областей в `moduleGrant`, роль на вкладке «Модели».
- Клиент не пересобирается: экраны из существующих компонентов.
- Токены: ожидаемая экономия на повторных вопросах — контекст 4 000 токенов
  заменяется кристаллом и фактами на 100–300; у Claude Code — начало сессии
  без повторного исследования репозитория. Проверяется журналом.
