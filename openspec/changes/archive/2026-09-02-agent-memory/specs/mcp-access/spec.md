## Purpose

Внешние агенты на той же машине — Claude Code, Codex и любой клиент MCP —
пользуются памятью Сёмы, а не своей. Сёма выступает сервером MCP: отдаёт
инструменты памяти, знает, кто подключился, и выдаёт ему ровно те области,
которые разрешил человек.

## ADDED Requirements

### Requirement: Сёма — сервер MCP

Сёма SHALL принимать подключения по протоколу MCP (stdio для локальных
клиентов, HTTP для удалённых) и отдавать инструменты памяти: вспомнить по
запросу, записать факт или урок, отметить начало и конец сессии. Никаких
других примитивов ядра (почта, файлы, секреты) через MCP SHALL NOT
выдаваться в этом изменении.

#### Scenario: Claude Code подключился

- **WHEN** в настройках Claude Code указан сервер памяти Сёмы
- **THEN** инструменты памяти видны агенту, а первое обращение появляется на
  экране «Память» как новый потребитель, ждущий выдачи областей

### Requirement: Потребитель и его области

Каждый клиент MCP SHALL представляться именем и рабочей папкой; Сёма SHALL
хранить его как потребителя с набором выданных областей. До выдачи областей
человеком потребитель SHALL получать отказ на любое обращение. Выдача и
отзыв SHALL делаться на экране «Память» без перезапуска клиента.

#### Scenario: Проект получает свою область

- **WHEN** человек выдаёт Claude Code в папке `~/projects/sema` области
  «код:sema» и «уроки»
- **THEN** в других папках тот же агент этих областей не видит

### Requirement: Сессия целиком

Начало сессии SHALL возвращать агенту короткий контекст из памяти: уроки
области, актуальные факты, кристалл прошлой сессии — в пределах лимита на
промпт. Конец сессии SHALL принимать сводку и наблюдения, из которых Сёма
делает кристалл и извлекает факты и граф. Примеры хуков для Claude Code и
Codex SHALL лежать в репозитории.

#### Scenario: Новая сессия без повторного исследования

- **WHEN** Claude Code начинает сессию в проекте, где вчера уже работал
- **THEN** он получает вчерашний кристалл и уроки проекта и не тратит токены
  на повторный поиск по репозиторию

### Requirement: Фильтр на входе от внешних агентов

Всё, что приходит от внешних агентов, SHALL проходить guardrails на входе
как любая запись; вывод инструментов агента SHALL проверяться масками
секретов особенно, потому что в нём чаще всего оказываются токены и пароли.

#### Scenario: Ключ в логе

- **WHEN** Codex прислал наблюдение с содержимым `.env`
- **THEN** строки с секретами отброшены, остальное сохранено, попытка в
  журнале
