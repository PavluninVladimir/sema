## Context

У Сёмы уже четыре слоя, похожих на память, и ни один не переносит знание
между разговорами: история одного чата (12 реплик), правила в инструкциях
модулей (`sema-rule`, с подтверждением), память скриптов (`store.get/set`,
зашифрована) и RAG по письмам и файлам. Контекст одного ответа стоит около
4 000 токенов (опись ~320, выписка чеков ~1 000, письма и файлы ~2 800) и
собирается заново на каждую реплику. Claude Code и Codex на той же машине
заново исследуют репозиторий каждую сессию.

Владелец решил: память одна на всех и живёт в Сёме; модель записей — как у
agentmemory (наблюдения → факты → уроки → кристаллы → граф) с происхождением
(сессия, агент, модель); области и guardrails настраиваются, а не зашиты.

## Goals / Non-Goals

**Goals:**

- Экономить токены: повторный вопрос стоит кристалл и пару фактов, а не
  полный контекст; новая сессия агента начинается с уроков, а не с поиска.
- Одно хранилище, одно происхождение, один журнал для Сёмы, модулей и
  внешних агентов.
- Разграничение областями и правила на входе и выходе, все — в базе и на
  экране.
- Всё на Go и SQLite: работает на Raspberry Pi без Node и внешних сервисов.

**Non-Goals:**

- Повторить все 54 инструмента agentmemory: нужны четыре (вспомнить,
  записать, начало и конец сессии).
- Выдавать по MCP что-либо, кроме памяти — почта, файлы, секреты через MCP
  придут отдельным изменением.
- Синхронизация памяти между машинами.
- Экономия токенов внутри одной сессии агента (чтение файлов) — это не
  память.

## Decisions

### Одна таблица записей с видом и происхождением, версии — цепочкой

`memories(id, kind, area, text, session_id, agent, model, created,
supersedes, confirmed_by, weight)`; `kind` ∈ observation | fact | lesson |
crystal. Новая версия факта ссылается на старую через `supersedes`; в
выдачу идут записи без наследников. Урок — факт, у которого `weight`
превысил порог из настроек или который подтвердил человек.

*Альтернатива:* отдельные таблицы под каждый вид — отклонено: журнал,
поиск и области у всех одинаковые, различается только срок жизни.

### Поиск — гибрид на том, что уже есть

BM25 через FTS5 (включён в modernc.org/sqlite, cgo не нужен), векторы через
существующий `embed` (bge-m3) и брутфорс-косинус как в `rag.go`, плюс обход
графа от сущностей, найденных в вопросе. Оценки складываются с весами из
настроек; переранжирование моделью — нет, дорого и не нужно на таких
объёмах.

### Граф — две таблицы и справочник типов

`nodes(id, type, name, area)`, `edges(from, to, relation, memory_id)`; типы
узлов и связей — таблица с первичным набором (поставщик, счёт, документ,
сервер, проект, решение, правило…), правится на экране. Каждое ребро
ссылается на запись, из которой извлечено, — так у ребра есть происхождение.
Извлечение делает роль «Память» по расписанию, не в момент ответа.

*Альтернатива:* встроенная графовая БД — отклонено: cgo, зависимости, а
обход на глубину два по SQLite укладывается в миллисекунды.

### Области — метка, потребители — строки с выданными областями

`memory_areas(name, title, outbound bool, confirm mode, ttl_days, forget bool)`;
`memory_consumers(id, kind, name, path, areas[])`, где kind ∈ chat | module |
mcp. Для модулей `Granted` областей хранится в манифесте рядом с секретами —
та же механика, тот же экран установки. Для MCP-клиентов потребитель
заводится при первом обращении с пустым набором областей.

*Альтернатива:* отдельные базы по областям — отклонено владельцем: память
должна быть общая.

### Guardrails — две функции с настройками в базе

`admit(record)` на входе: маски секретов (`memory_rules` kind=mask, первичный
набор — `enc:v1:`, `sk-`, `glpat-`, `-----BEGIN`, `password=`), область
«не запоминать», размер, режим подтверждения. `release(consumer, model,
records)` на выходе: выданные области, `outbound` для облачной модели,
лимиты на промпт, срок жизни. Обе пишут в `memory_log` с оценкой токенов.
Значения по умолчанию только сеют справочник.

### Облачной модели закрыто по умолчанию

`outbound=false` у всех областей при создании; человек открывает вручную.
Цена — облачный чат первые дни беднее; принято осознанно, по духу хранилища
секретов. Локальная модель видит все выданные области.

### MCP — свой маленький сервер

Протокол MCP на JSON-RPC простой; пишем `internal/mcp` на стандартной
библиотеке: stdio-транспорт для локальных клиентов и HTTP для удалённых,
четыре инструмента. Клиент представляется именем и папкой (`initialize` +
аргумент папки в хуке). Хуки: Claude Code — `SessionStart` → recall,
`Stop`/`SessionEnd` → session_end со сводкой; Codex — MCP-инструменты плюс
инструкция в его конфиге вызывать их в начале и в конце.

*Альтернатива:* готовая Go-библиотека MCP — допустимо, если не тянет cgo и
тяжёлые зависимости; решается при реализации.

### Консолидация — задача сердцебиения ролью «Память»

Раз в час: слияние близких записей (косинус выше порога и один смысл по
мнению модели) в одну с несколькими источниками; повторы повышают `weight`;
эпизоды старше `ttl_days` сжимаются в кристалл; наблюдения старше срока
удаляются. Без модели на роли — только удаление по сроку.

### Чат: память раньше писем

`chatAnswer` собирает контекст в порядке: уроки области → факты и кристаллы
по гибридному поиску → обход графа → и только потом письма, файлы и чеки,
если лимит не исчерпан и ответа в памяти нет. Предложение запомнить — блок
```sema-remember:<область>``` в ответе модели, карточка в переписке, как
`sema-rule`. Кристалл чата — при его закрытии или по бездействию.

## Risks / Trade-offs

- **Память врёт увереннее, чем поиск.** Устаревший факт в промпте хуже
  отсутствия. Смягчение: версии, происхождение на виду, консолидация,
  «ответ по данным» из спеки чата остаётся в силе.
- **Внешний агент приносит мусор.** Наблюдения Claude Code многословны;
  без роли «Память» они не сожмутся. Смягчение: срок жизни наблюдений и
  лимит на запись.
- **Секреты в памяти.** Маски ловят не всё. Смягчение: список масок
  правится, журнал показывает отвергнутое, облачной модели закрыто по
  умолчанию.
- **Граф разрастается.** Извлечение по расписанию и справочник типов
  ограничивают; обход всегда на глубину из настроек.
- **Первые дни память пустая**, экономии нет и ответы облачной модели
  беднее. Это видно в журнале, и это честная цена.
