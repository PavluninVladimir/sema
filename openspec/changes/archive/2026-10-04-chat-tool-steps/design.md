## Context

Зачем — см. proposal.md.

- Сейчас ход чата устроен так:
  - **ход 1** — модель отвечает и может прислать блоки (`sema-ssh`,
    `sema-mcp`, `sema-search`, скрипты);
  - **ход 2** — модель видит результаты читающих блоков и пишет итог;
  - блоки второго хода выполняются, но их результат модель уже не видит:
    `engine/chat.go`, комментарий «третьего хода нет — иначе модель ходит
    по кругу».
- Результат MCP режется по рунам до `mcp.chat_result_chars` (6000) —
  сырой JSON, вместе с заметками, цветами и датами.
- Пинатель (`engine/nudge.go`) смотрит только на чаты команд
  (`workChats` — чаты со сроком `chat.expires.*`) и чаты собеседников,
  которым нужен ответ. Админ-чат Telegram и его ветка «Сёма» в него не
  попадают.

## Goals / Non-Goals

**Goals:**
- Задача «найти, потом сделать» проходит в одном обращении человека, если
  поиск — чтение.
- Модель видит из длинного ответа то, что нужно для выбора, а не начало
  JSON.
- «Проверю» без действия до человека не доходит.

**Non-Goals:**
- Длинная работа на часы с подзадачами — это `work-until-done`.
- Изменяющие вызовы без кнопки: правила доступа не меняются.

## Decisions

### 1. Шаги вместо «двух ходов»

```
 ход 1 --> блоки --> выполнены
   |
   v
 ход 2..N: модель видит результаты
   +-- только читающие блоки и шагов < chats.read_steps --> выполнить, следующий ход
   +-- изменяющий блок --> карточка с кнопкой, ход кончается
   +-- блоков нет --> итог человеку
```

Читающий — то, что сегодня выполняется без кнопки: MCP «Разрешить»,
`sema-search`, SSH из круга чтения, чтение страниц. Предел шагов
`chats.read_steps` (4) — в реестре. На каждом шаге действует
`budgetCheck`. Шаги пишутся в журнал, чтобы был виден путь. Прежний
страх «модель ходит по кругу» закрывает решение 3: повтор того же вызова
не исполняется.

### 2. Сжатый ответ для модели

Если ответ инструмента — JSON-массив (или объект с массивом `items`) и
длиннее предела, модель получает **выжимку**:
- по каждому элементу — поля из списка `mcp.chat_list_fields`
  (по умолчанию `id, title, name, projectId, parent, state, checked`), что
  из них есть;
- строку «показано N из M; подробнее о записи — `*_get` по id;
  следующая порция — `offset`/`maxCount`», если инструмент такие
  аргументы принимает (видно по `tool_info`).

Если выжимка тоже не влезает — она режется по элементам, а не посреди
JSON, с названным остатком. Карточка, журнал и «Что ушло наружу» хранят
полный ответ.

### 3. Тот же вызов дважды подряд

Ключ — инструмент плюс нормализованные аргументы. Повтор в пределах
одного обращения не исполняется: модель получает «ты уже звал это, вот
результат» и выжимку. Повтор с другими аргументами (следующая порция) —
законный.

### 4. Обещание без действия

После итогового хода — проверка:
- в тексте есть слово-примета обещания из справочника
  `promise_markers` (засев: «проверю», «сделаю», «создам», «заведу»,
  «сейчас посмотрю», «займусь», «поищу»);
- в ответе нет ни одного блока.

Тогда, если шаги ещё остались, текст человеку не уходит, а модель
получает: «Ты пообещал действие, но не сделал его. Сделай блоком сейчас
или прямо скажи, чего не хватает». Это не больше одного раза за
обращение. Если и второй ответ — обещание, человеку уходит он, с
пометкой «Сёма не сделал обещанное» в журнале. Справочник правится на
экране «Работа Сёмы → Чаты и ветки».

## Risks / Trade-offs

- [Больше ходов — больше денег] → предел шагов в реестре, бюджеты на
  каждом шаге, в журнале путь целиком.
- [Ложное «обещание»: «проверю завтра» — законный ответ] → один возврат,
  а не цикл; справочник правит человек.
- [Выжимка выкинет нужное поле] → поля — настройка; подсказка про
  `*_get`; в карточке полный ответ.

## Migration Plan

1. Сжатый ответ MCP.
2. Повтор одного вызова.
3. Шаги читающих вызовов.
4. Обещание без действия.

После каждого шага — проверка на поддельной модели: «найди проект „Сёма“
среди 43 и заведи в нём задачу» проходит одним обращением.
