## Why

Хранилище ключей уже умеет генерировать ключи SSH и держит приватную часть
закрытой «для будущего примитива ssh». Самого примитива нет: Сёма не может
зайти на сервер и посмотреть логи, хотя именно этот сценарий владелец
называл первым («скажу Сёме подключиться к серверу и посмотреть логи»).
Модуль «Серверы» из макетов без него невозможен.

Доступ к серверам — самое опасное, что Сёма делает наружу, поэтому он
должен быть устроен как секреты: ключ по имени, права поимённо, журнал
каждой команды, а изменяющие команды — только с подтверждением человека.

## What Changes

- Справочник серверов: имя, адрес, порт, пользователь, ключ из хранилища по
  имени; отпечаток хоста запоминается при первом входе (TOFU), смена
  отпечатка — отказ.
- Примитив `ssh` ядра на чистом Go: берёт приватный ключ из хранилища сам,
  наружу не отдаёт; таймаут и предел вывода — настройки.
- Два списка команд в базе: «только чтение» (выполняются без вопроса) и
  «никогда» (отказ всегда); всё остальное — подтверждение человеком на
  каждую команду. Кнопка «Выполнить и добавить в чтение» пополняет список.
  `sudo` всегда требует подтверждения. Вывод проходит маски секретов.
- Журнал команд: сервер, кто (чат, модуль, задача), команда, код выхода,
  время, размер вывода; обращение к ключу фиксируется в журнале секретов.
- Чат: модель просит выполнить команду блоком ```sema-ssh:<сервер>```;
  разрешённая выполняется сразу с карточкой вывода, остальные ждут кнопки.
- Модули: `ssh: ["prod-1"]` в манифесте, выдача по серверу тумблером при
  установке, `sema.ssh.run(host, cmd)` только по выданным; скрипты из чата
  получают заглушку.
- Вкладка «Серверы» в настройках: список, добавление, отпечаток, проверка
  связи, ожидающие команды, журнал, списки команд. Макеты до кода.

## Capabilities

### New Capabilities

- `ssh-access`: справочник серверов, примитив ssh, guardrails по командам,
  подтверждение, журнал, экран «Серверы».

### Modified Capabilities

- `modules`: поле `ssh` в манифесте, выдача серверов поимённо, примитив в
  песочнице.
- `assistant-chat`: блок команды SSH в ответе модели, карточки выполнения и
  подтверждения, второй ход модели по выводу.
- `secrets-vault`: приватная часть ключа SSH выдаётся только примитиву ssh
  ядра по имени сервера, обращение видно в журнале секрета.

## Impact

- `server/go.mod`: `golang.org/x/crypto/ssh` (чистый Go, кросс-компиляция
  под Pi сохраняется).
- `server/internal/store`: таблицы `hosts`, `host_keys` (отпечатки),
  `ssh_rules` (чтение / никогда), `ssh_log`, `ssh_pending`.
- `server/internal/sshx` (новый): подключение по ключу из хранилища,
  выполнение команды с таймаутом и пределом вывода, проверка отпечатка.
- `server/internal/engine`: `ssh.go` (правила, подтверждение, журнал,
  маски), `ssh_chat.go` (блок в ответе, карточки, второй ход), правки
  `modules.go`/`scripts.go` (`ssh` в манифесте, `sema.ssh.run`, заглушка),
  `secrets.go` (выдача ключа примитиву с записью в журнал).
- `server/internal/api`: `settings_servers.go` (вкладка «Серверы»),
  карточки SSH в чате, строки серверов в `moduleGrant`, действия.
- Клиент не пересобирается.
