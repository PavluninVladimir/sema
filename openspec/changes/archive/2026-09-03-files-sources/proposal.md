## Why

Файл теперь самостоятельная сущность с источником, но источников у него по
сути два: письмо и перетаскивание в окно. Скан с телефона падает в папку на
диске, модуль, снявший отчёт с сервера, не может положить его в файлы, а в
чате нельзя показать Сёме документ и спросить о нём. Ядро уже умеет
принимать файл откуда угодно (`AddFile`), не хватает самих источников.

## What Changes

- **Папки на диске.** Справочник наблюдаемых папок на экране «Хранилища»:
  путь внутри сервера (в Docker — примонтированный том, по умолчанию
  `/data/inbox`), включена ли, удалять ли файл после приёма. Задача «Папки с
  файлами» раз в минуту забирает новые файлы: источник `folder:<путь>`,
  дедупликация по хэшу, уже принятые помнятся по пути, размеру и времени.
- **Файлы от модулей.** `sema.files.add(name, content, {mime, base64})` по
  праву `files`: модуль кладёт файл в хранилище, источник `module:<имя>`,
  событие `file.added` идёт остальным модулям. `sema.files.text(id)` — текст
  файла по id.
- **Файл в чат.** Перетаскивание на экран чата загружает файл с источником
  «загрузка · чат» и добавляет в переписку сообщение с чипом файла; файл
  попадает в контекст ответа (по имени и по номеру `#id`) и открывается из
  чипа через сервер.

## Capabilities

### Modified Capabilities

- `files-storage`: источники «папка» и «модуль», справочник папок.
- `files-access`: файл в чат.
- `modules`: `sema.files.add`, `sema.files.text`.
- `assistant-chat`: файл, присланный в чат, в контексте ответа.

## Impact

- `store/files.go`: таблицы `file_folders`, `folder_seen`.
- `engine/filestore.go`: `foldersPass` (задача `files_folders`), `AddFile`
  для папки; `engine/scripts.go`: `files.add`, `files.text`.
- `api/storages.go`: справочник папок с формой; `api/chat`: чип файла в
  сообщении; клиент: drop на экран чата.
- Docker: пример монтирования папки в `docker run` и compose.
