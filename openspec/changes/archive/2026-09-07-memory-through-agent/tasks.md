# Задачи

Порядок такой, чтобы на каждом шаге всё работало: сначала новая дорога
рядом со старой, потом переключение, и только последним шагом снос HTTP.

## 1. Провод в обе стороны

- [x] 1.1 Житель машины умеет слать запросы Сёме: карта незакрытых вызовов
      по `id`, разбор ответа, запись в соединение под тем же замком, что и
      пинг (`agent/internal/link/link.go`)
- [x] 1.2 Сёма принимает запросы агента: разбор кадра, поиск обработчика по
      имени возможности, ответ или понятная ошибка без разрыва соединения
      (`server/internal/engine/agent_serve.go`)
- [x] 1.3 Неразрешённая возможность — отказ с объяснением, где включить;
      соединение остаётся живым, попытка в журнале
- [x] 1.4 Обращение агента к Сёме идёт в журнал так же, как обращение Сёмы
      к агенту
- [x] 1.5 Тест: запрос и ответ по проводу переживают перезапуск Сёмы —
      агент повторяет, клиент разницы не видит

## 2. Способность «память» и области

- [x] 2.1 Способность «память» объявляется агентом и появляется выключенной
      на экране «Агенты», как «код»
- [x] 2.2 Сёма зовёт обработчики памяти только при включённой способности;
      отзыв действует немедленно
- [x] 2.3 Рабочая папка приходит параметром каждого запроса, а не живёт
      состоянием соединения
- [x] 2.4 Потребитель ищется по паре «имя агента плюс папка», области
      выдаются на «Памяти» как раньше — экран не меняется
- [x] 2.5 Тест: способность включена, области для папки не выданы — отказ;
      выданы одной папке — из другой отказ

## 3. Инструменты памяти у жителя машины

- [x] 3.1 Пять инструментов в реестре `cmd/semaagent/mcp.go`:
      `memory_recall`, `memory_remember`, `memory_session_start`,
      `memory_session_end`, `code_knowledge`
- [x] 3.2 Каждый инструмент кладёт рабочую папку в запрос и переносит ответ
      Сёмы как есть, не пересказывая
- [x] 3.3 Сёма недоступна — инструмент отвечает понятной ошибкой, а не
      пустотой: видно, что дело в связи, а не в пустой памяти
- [x] 3.4 `tools/list` отдаёт двенадцать инструментов: семь кода и пять
      памяти
- [x] 3.5 Тест: вызов инструмента памяти при оборванном проводе даёт
      ошибку про связь и не роняет сервер MCP

## 4. Хуки через бинарник

- [x] 4.1 `semaagent -hook <вид>` читает JSON события со стандартного входа
- [x] 4.2 Определение корня работы переезжает из shell в Go: git-корень, а
      если у родителя есть `CLAUDE.md` и нет `.git` — родитель; тест на обе
      ветки
- [x] 4.3 Четыре вида событий: начало сессии, заметка, конец сессии,
      заметка субагента
- [x] 4.4 Хук завершается с нулевым кодом всегда, даже когда житель машины
      не отвечает
- [x] 4.5 `common.sh` у Claude Code и Codex теряет `post()` и токен;
      скрипты сжимаются до вызова бинарника
- [x] 4.6 Примеры настроек в `integrations/` обновлены: без `SEMA_TOKEN`,
      без `SEMA_URL`

## 5. Обрыв связи виден

- [x] 5.1 Сёма помнит время последнего разговора с каждым агентом
- [x] 5.2 Обрыв соединения даёт уведомление с временем последнего
      разговора, уровень «внимание», ключ по имени агента
- [x] 5.3 Возвращение агента закрывает уведомление само и говорит, сколько
      времени связи не было
- [x] 5.4 У выключенного человеком агента обрыв уведомлений не порождает
- [x] 5.5 На «Агентах» рядом со счётом сбережённого кодом видно, когда было
      последнее обращение к памяти и сколько их за сутки
- [x] 5.6 Тест: обрыв, возвращение, повторный обрыв — уведомление одно, не
      копится

## 6. Переезд на живой машине

- [x] 6.1 Сёма выкатывается с проводом и старыми ручками разом: ничего не
      ломается
- [x] 6.2 Житель машины пересобран и перезапущен с инструментами памяти
- [x] 6.3 Способность «память» включена человеком на экране «Агенты»
- [x] 6.4 Проверка на живом: `memory_recall` через жителя машины отвечает,
      обращение видно в журнале памяти с той же папкой
- [x] 6.5 Из `~/.claude.json` убран сервер `sema-memory`; проверено, что
      инструменты памяти приходят от `sema-agent`
- [x] 6.6 Из окружения хуков убран `SEMA_TOKEN`, хуки переведены на
      бинарник; проверено на живой сессии в двух папках
- [x] 6.7 Проверка: перезапуск Сёмы посреди сессии не ломает память

## 7. Снос HTTP

- [x] 7.1 Из Сёмы удалены маршруты `/mcp` и `/api/memory/session_*`
- [x] 7.2 Из `internal/mcp` удалена HTTP-обвязка: разбор запроса, карта
      сессий, коды ответов; описания инструментов и вызовы в движок
      остаются
- [x] 7.3 Из жителя машины удалён `serveHTTP` и флаги `-listen`, `-token`
- [x] 7.4 `CLAUDE.md` зонтика и `agent/CLAUDE.md` описывают новую дорогу;
      старая не упоминается как рабочая
- [x] 7.5 Полный прогон тестов в обоих репозиториях, выкат, проверка на
      живом

**Ворота:** после шага 6 память работает через жителя машины и переживает
выкат Сёмы; после шага 7 в конфигурациях агентов разработки нет ни одного
секрета, а к памяти нет ни одного пути по сети.
