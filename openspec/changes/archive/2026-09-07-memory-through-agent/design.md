## Context

См. `proposal.md` — Why. Здесь только то, что определяет форму решения.

**Провод сегодня односторонний.** `internal/link/link.go` у жителя машины
умеет принимать запросы (`c.handlers[req.Method]`) и отвечать на них, а
отправляет сам только `hello` и `ping`. Со стороны Сёмы есть `AskAgent`
(`engine/agent_serve.go`), обратного нет. Соединение одно, кадры JSON-RPC с
`Content-Length`, писать в него можно только под замком: без него пинг и
ответы обработчиков перемешиваются, и это уже случалось.

**Инструменты MCP у агента уже есть.** `cmd/semaagent/mcp.go` держит реестр
инструментов, `tools/list`, `tools/call` и два рта: stdio и HTTP. Семь
инструментов кода объявлены в `main.go`. Добавить пять инструментов памяти
— это записи в том же реестре.

**Инструменты памяти у Сёмы тоже есть.** `internal/mcp/mcp.go` содержит и
описания, и вызовы в движок. С них снимается только HTTP-обвязка: разбор
запроса, карта сессий `clients[Mcp-Session-Id]`, коды ответов.

**Хуки — четыре коротких скрипта на каждого агента разработки.** Все шлют
JSON на `$SEMA_URL` с `$SEMA_TOKEN` через `post()` в `common.sh`. Точка
смены одна на всех.

**Потребитель памяти — пара «имя агента плюс рабочая папка».** Так области
и выдаются на экране «Память». Это остаётся: житель машины лишь передаёт
папку, от имени которой пришёл вопрос.

## Goals / Non-Goals

**Goals:**

- Перезапуск Сёмы не виден агенту разработки: обращение к памяти либо
  проходит, либо ждёт восстановления провода, но не требует человека.
- Ни одного секрета в конфигурации агентов разработки: доступ даёт
  сертификат жителя машины, а не строка в файле.
- Одна дверь: и код, и память приходят от одного сервера MCP по stdio.
- Обрыв постоянного соединения виден человеку сразу и закрывается сам.

**Non-Goals:**

- Права модулей и чатов на память не меняются: речь только о внешних
  агентах разработки.
- Правила самой памяти (области, guardrails, консолидация) не трогаются.
- Работа памяти с машин, где нет жителя, не сохраняется. Это осознанное
  сужение, названное в предложении.
- Общий HTTPS Сёмы не трогается: веб-клиент, пуши, файлы, вход агента по
  приглашению, здоровье и будущие webhook'и остаются как есть.

## Decisions

### 1. Провод, а не HTTP внутри агента

Житель машины мог бы ходить к Сёме по HTTP с токеном и повтором: кода
меньше втрое. Отвергнуто: тогда токен просто переезжает из конфигурации
Claude Code в конфигурацию агента, а правило «HTTP запасным путём не
служит» обходится стороной. По проводу доступ даёт сертификат, а
способность «память» человек выдаёт тумблером рядом со способностью «код».

Поверхность инструментов у обоих путей одинаковая, поэтому выбор транспорта
ничего не стоит клиентам: они видят те же пять инструментов.

### 2. Направление вызовов симметрично тому, что уже есть

Кадр агента к Сёме — тот же JSON-RPC с `Content-Length`, что и в обратную
сторону: метод вида `память.recall`, параметры объектом, `id` для ответа.
Агент ведёт карту незакрытых запросов, ответ Сёмы разбирается по `id`.
Запись в соединение идёт под тем же замком, что и `ping`.

Альтернатива — второе соединение для обратного направления — отвергнута:
удваивает и сертификаты, и переподключение, и обрывы, а выигрыша не даёт.

### 3. Рабочая папка едет в каждом запросе

Житель машины один, а папок много. Папка приходит параметром запроса, а не
берётся из состояния соединения: так разделение по проектам сохраняется без
понятия «текущая папка» на проводе, которого у постоянного соединения быть
не может.

Сёма по паре «имя агента плюс папка» находит потребителя и его области, как
делала для клиента MCP. Экран «Память» не меняется.

### 4. Способность «память» и области — два разных замка

Способность включается на экране «Агенты» и отвечает на вопрос «можно ли
этому агенту вообще спрашивать память». Области выдаются на экране «Память»
и отвечают на вопрос «что именно он увидит из этой папки». Ни один не
заменяет другой: способность без областей даёт отказ, области без
способности не спрашиваются.

Альтернатива — свести всё к областям — отвергнута: тогда включение памяти
агенту размазывается по проектам, и нет одного места, где видно «этот агент
к памяти допущен».

### 5. Хуки зовут бинарник, а не сеть

`common.sh` теряет `post()` с токеном и получает вызов `semaagent` с
подкомандой. Бинарник уже стоит на машине, уже держит провод, уже опознан.
Хук становится короче и перестаёт знать адрес Сёмы.

Цена названа честно: хук перестаёт работать, когда жителя машины нет.
Раньше он работал и без него. Смягчение — в решении 6: пропажа видна.

Альтернатива — оставить хукам HTTP — отвергнута по решению человека: одна
дверь, а не полторы.

### 6. Обрыв — событие, тишина выключенного — нет

Соединение постоянное, поэтому обрыв известен точно, а не выводится из
молчания: порога тишины не заводим. Уведомление появляется по обрыву,
закрывается само по возвращении и говорит, сколько связи не было. Ключ
уведомления — имя агента, поэтому вторая пропажа заменяет первую, а не
копится.

Уровень «внимание», не тревога: мак спит по ночам, и ночной обрыв это
норма жизни, а не поломка. Тому, кому агент сейчас не нужен, положено
выключить его на экране «Агенты» — у выключенного обрыв молчит.

Отдельно отмечено: тихие часы канала доставки продолжают действовать, так
что ночная запись не будит телефон, а ждёт утра в «Уведомлениях».

### 7. HTTP уходит целиком, но только путь памяти

Из Сёмы удаляются `/mcp` и `/api/memory/session_start|note|end`. Из жителя
машины удаляется `serveHTTP` — рот, оставшийся с тех пор, когда Сёма ходила
к агенту по сети; сейчас она ходит по проводу, и второй путь только
расширяет поверхность.

Право токена «память» остаётся в справочнике прав: оно ничего не открывает,
пока нет ручек, которые его спрашивают, а удаление права из уже выданных
токенов человеку ничего не даёт.

### 8. Хук — один флаг и разбор JSON внутри жителя машины

`semaagent -hook <вид>` читает тот же JSON со стандартного входа, что
приходит хуку от Claude Code и Codex, и сам достаёт из него рабочую папку,
текст и вид события. Скрипт хука сжимается до одной строки.

Так уходит дублирование, которое сегодня стоит дорого: определение корня
работы (`git rev-parse --show-toplevel`, а если у родителя лежит
`CLAUDE.md` и нет `.git` — берём родителя) написано на shell и повторено в
`claude-code/common.sh` и `codex/common.sh`. В Go оно одно и покрывается
тестом.

Четыре отдельных флага отвергнуты: четыре почти одинаковые ветки ради
экономии одного слова в командной строке.

Хук SHALL завершаться с нулевым кодом всегда, даже когда житель машины не
отвечает: сессия агента разработки не должна падать из-за памяти. Молчание
не прячется — оно видно уведомлением об обрыве из решения 6.

### 9. На «Агентах» видно, живёт ли память

В строке агента рядом со счётом сбережённого кодом появляется вторая
строка про память: когда было последнее обращение и сколько их за сутки.

Причина простая: житель машины становится единственной дверью, и когда
память замолчит, человек пойдёт смотреть именно сюда. Без этой строки
единственное свидетельство лежит на другом экране, в журнале памяти.

Полноценной статистики здесь не заводим: два числа, оба уже считаются в
журнале памяти.

### 10. Местная дверь — сокет, а не порт

Решение 7 сносит у жителя машины сетевой рот, но через него к демону
ходили и обёртки агентов разработки: языковой сервер должен подниматься
один раз на всех, иначе у каждого окна свой пул. Дверь нужна — вопрос
только какая.

Выбран сокет `~/.sema-agent/agent.sock` с правами 0600: он даёт ровно то
же, что порт с токеном, но без строки, которую можно подсмотреть,
скопировать в чужую папку и забыть отозвать. Токен в конфигурации — это
тот самый секрет, ради избавления от которого всё затевалось; оставить
его ради удобства значило бы отменить смысл работы.

Роль процесса решает не флаг, а дверь: демон тот, кто держит провод к
Сёме (`-link`), остальные приходят к нему. Флаги `-listen`, `-token` и
`-connect` убраны совсем.

Соединение обёртки постоянное — не ради скорости, а ради памяти: демон
запоминает по нему, кто на том конце (из `initialize`), и области
выдаются тому, кто пришёл.

### 11. Имя спрашивающего едет параметром

За одним проводом сидят Claude Code и Codex, а потребитель памяти — пара
«кто спрашивает плюс папка». Подставить сюда имя жителя машины значило бы
слить их в одного потребителя с одной сессией на двоих и отрезать от уже
выданных областей: они выданы именам «Claude Code» и «Codex».

Поэтому имя приходит параметром `client` и берётся из `initialize`
клиента (у хука — из флага `-agent`). Проверять его нечем и незачем:
житель машины на этой машине свой, а раньше клиент MCP называл себя ровно
так же. Способность «память» при этом проверяется по имени из
сертификата — подменить его нельзя.

## Risks / Trade-offs

**Житель машины становится единой дверью и для кода, и для памяти.** Не
поднялся — нет ни карточек кода, ни памяти. → Пропажа видна сразу с двух
сторон: у клиента инструменты не появляются, у Сёмы возникает уведомление.
Автозапуск через launchd уже настроен.

**Хуки начинают зависеть от агента.** Раньше `curl` работал всегда. →
Хук, не достучавшийся до жителя машины, завершается тихо и с нулевым кодом,
как сейчас: сессия агента разработки не должна падать из-за памяти.

**Память недоступна с машин без жителя.** → Осознанное сужение. Если
понадобится вторая машина, на неё ставится житель и заводится приглашением,
как первый.

**Обратное направление в проводе — новая поверхность.** Агент получает
возможность звать Сёму. → Зовёт он только разрешённые способности, каждый
вызов в журнале, отзыв мгновенный. Список возможностей закрытый: память и
ничего больше.

**Ночные обрывы могут утомить.** Мак спит каждую ночь. → Уровень
«внимание», самозакрытие по возвращении, тихие часы канала. Если утомит
всё равно — у агента есть выключатель, и это правильный ответ, а не порог.

## Migration Plan

1. Выкатывается Сёма, умеющая и провод, и старые ручки: ничего не ломается.
2. Ставится житель машины с инструментами памяти; в Claude Code остаётся
   прежний сервер `sema-memory` рядом с новым.
3. Человек включает агенту способность «память» на экране «Агенты».
4. Проверка: `memory_recall` через жителя машины отвечает, обращение видно
   в журнале памяти с той же папкой.
5. Из настроек Claude Code и Codex убирается сервер `sema-memory`, из
   окружения хуков убирается `SEMA_TOKEN`, хуки переводятся на бинарник.
6. Следующим выкатом из Сёмы удаляются `/mcp` и `/api/memory/*`, из жителя
   машины — `serveHTTP`.

Откат: до шага 6 достаточно вернуть сервер `sema-memory` в настройки и
токен в окружение. После шага 6 откат — предыдущий образ Сёмы плюс копия,
как при любом обновлении.
