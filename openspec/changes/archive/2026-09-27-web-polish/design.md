## Context

См. `proposal.md` и `design/UX-AUDIT-WEB.md` — там 368 расхождений с
числами. Здесь только решения, которые определяют форму правок.

## Goals / Non-Goals

**Goals:** веб-клиент выглядит по макетам; правила остаются в одном месте
(токены и шаблон), а не расползаются по экранам; данные, которые портят
экран, чинятся в источнике.

**Non-Goals:** новые экраны; переделка UI-DSL под веб (словарь общий);
правка модулей руками — их код правит модель через чат.

## Decisions

### 1. Значки — свой набор по именам SF Symbols

Сервер уже шлёт `icon` именами SF Symbols. Веб получает свой набор
`internal/web/icons.go`: одна сетка 16×16, обводка 1.5, цвет от текста.
Имени нет в наборе — значка нет: пустой кружок вместо смысла хуже, чем
ничего. Так словарь не меняется, а рисуют оба клиента одинаково.

### 2. Строка настройки вместо «подпись сверху, поле во всю ширину»

`.поле` стало сеткой «подпись слева — управление справа» с колонкой
120–300px. Это одно правило чинит формы на всех экранах сразу: пределы
очереди, доступ, хранилища, ящики.

### 3. Одно действие в строке — и в шапке тоже

Правило «в строке одно действие» действовало только для строк. У шапки
такого не было, и в чате она переносилась в два ряда. Документ получил
`toolbarMenu`: главное кнопкой, остальное под «…».

### 4. Мета рядом с названием — поле, а не догадка

Список писем требует «отправитель + адрес и время в одну линию, тема
ниже». Вместо особого случая для почты в DSL появилось `metaInline`:
строка сама говорит, как показывать мету.

### 5. Данные чиним в источнике

Превью с CSS и обломками Office чинится в `mail.cleanSnippet` и разовым
проходом по сохранённым, а не пряткой в интерфейсе. Причина «папка INBOX»
не показывается, потому что ничего не объясняет.

## Risks / Trade-offs

**Правки в общем шаблоне видны на всех экранах** → после каждой волны
снимаются экраны и сверяются глазами; снимки лежат рядом с аудитом.

**Значков в наборе меньше, чем имён у сервера** → недостающее имя не
ломает экран: значка просто нет, а список набора растёт по мере надобности.
