## Context

`usage` хранит расход по потребителям, `UsageFor(prefix, since)` считает
сумму за период. Модуль умеет выключаться с причиной (`Broken`), задача —
`SetTaskEnabled`. Точка в меню и пороги — `HealthCards`.

## Goals / Non-Goals

**Goals:**

- Один лишний ноль в скрипте не съедает месячный лимит облака.
- Лимиты — данные, а не код; их видно рядом с расходом.

**Non-Goals:**

- Автоматическое снятие паузы по наступлении нового периода — пауза
  снимается руками, чтобы причина не осталась незамеченной.
- Бюджеты на время работы: считаем токены и деньги.

## Decisions

### Бюджет — строка справочника, проверка — в ядре перед моделью

`usage_budgets(id, consumer, kind tokens|money, period day|week|month,
limit, action warn|pause, created)`. `consumer` — точное имя
(`module:receipts`) или вид (`module`, `script`, `chat`, `core`). Проверка
`budgetCheck(consumer)` перед вызовом модели: для каждого бюджета,
подходящего потребителю, расход за период по `UsageFor` сравнивается с
лимитом; превышение — ошибка «бюджет исчерпан: модуль «Чеки», 50 000
токенов в день» и строка `run` с ok=0 в журнале, чтобы отказ был виден в
ленте. Действие `pause`: модуль — `EnableModule(false)` с `Broken`, задача —
`SetTaskEnabled(false)` с результатом, чат — отказ в ответе.

*Альтернатива:* блокировать в провайдере — отклонено: провайдер не знает
про модули и задачи.

### Точки проверки

`AskRole` (чат, память, модули через `sema.llm`), `toolAsk`/`Ask`,
`classify` (фильтр писем, `core:poll`), `imageText` (зрение,
`core:attachments`). Потребитель берётся из контекста — тот же, что для
журнала.

### На экране

Секция «Бюджеты» на «Здоровье»: строка на бюджет с полосой расхода к
лимиту (день/неделя/месяц — свой период у каждого), капсулы «осталось» и
«предупредить/пауза», действия «Изменить лимит», «Удалить». Форма: кому
(список известных потребителей плюс виды), чего, период, лимит, действие.
Точка в меню: жёлтая от 80 % любого бюджета, красная при превышении.
Карточка модуля и задача — капсула «бюджет N %».

## Risks / Trade-offs

- **Один вызов может перескочить лимит** — проверяем до вызова, не режем
  ответ пополам. Приемлемо.
- **Дорогая проверка на каждый вызов** — одна сумма по индексу
  `(consumer, at)`, бюджетов единицы.
