## 1. Хранилище

- [x] 1.1 Таблица секретов: имя, вид, значение (закрытое), кем создан, когда добавлен
- [x] 1.2 Добавление, замена, удаление; отказ добавлять без ключа шифрования с объяснением
- [x] 1.3 Значение не покидает сервер: ни в описании экрана, ни в ответах на действия

## 2. Права поимённо

- [x] 2.1 Поле `secrets` в манифесте модуля; разбор терпимый к форме записи
- [x] 2.2 Экран подтверждения: каждый секрет отдельной строкой, выдача по одному
- [x] 2.3 Примитив `sema.secret(name)` в песочнице модуля — только выданные имена, одинаковый отказ для невыданных и несуществующих
- [x] 2.4 Выдача и отзыв доступа с экрана хранилища без переустановки модуля

## 3. Ключи SSH

- [x] 3.1 Генерация ed25519 внутри Сёмы; приватная часть закрыта, публичная показывается с подсказкой, куда добавить
- [x] 3.2 Импорт существующего ключа как исключение, с предупреждением
- [x] 3.3 Приватная часть недоступна из модулей напрямую — только будущему примитиву `ssh` по имени

## 4. Журнал

- [x] 4.1 Запись каждого обращения: секрет, кто, когда, выдан или отказано
- [x] 4.2 Последнее обращение в списке, история по клику; сворачивание старых записей в счётчик

## 5. Память скриптов и скрипты из чата

- [x] 5.1 Шифрование памяти скриптов (`store.get/set`) тем же слоем; перешифровка существующих записей при старте
- [x] 5.2 Скрипты из чата без `sema.secret`; понятная ошибка и предложение оформить модуль

## 6. Витрина

- [x] 6.1 Экран «Ключи и секреты»: свои записи и чужие (ящики, модели, токен почты) с пометкой «используется: …»
- [x] 6.2 Действия: добавить, заменить, отозвать доступ, удалить, журнал
- [x] 6.3 Макеты экрана и формы добавления согласованы с владельцем до реализации

## 7. Проверка

- [x] 7.1 На живой системе: модуль с выданным и невыданным секретом, генерация ключа, журнал, скрипт из чата без доступа
