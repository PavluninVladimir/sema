## MODIFIED Requirements

### Requirement: Команды делятся на три круга

Сёма SHALL хранить в базе два списка образцов команд: «только чтение»
(выполняются без вопроса) и «никогда» (отказ всегда). Команда, не попавшая
ни в один список, а также любая команда с `sudo`, SHALL выполняться только
после подтверждения человеком, и подтверждение SHALL спрашиваться на каждую
такую команду. Первичный набор списков SHALL быть только заполнением
справочника; оба списка SHALL правиться на экране.

Образец, содержащий `*`, SHALL сравниваться как маска (`*` — любые символы),
чтобы одно правило покрывало семейство команд, например `/* print*` для всех
`print` RouterOS. Справочник чтения SHALL с первого запуска включать команды
обзора Linux (обновления, пакеты, входы, порты, WireGuard, fail2ban,
перезапуски служб) и RouterOS (ресурсы, обновления, журнал, активные
пользователи, WireGuard), а «никогда» — сброс конфигурации и удаление файлов
RouterOS.

#### Scenario: Логи без вопроса

- **WHEN** просят `journalctl -u nginx -n 50` на `prod-1`
- **THEN** команда выполняется сразу, вывод показан карточкой

#### Scenario: Перезапуск службы

- **WHEN** просят `systemctl restart nginx`
- **THEN** появляется карточка «требует подтверждения» с кнопками
  «Выполнить», «Выполнить и добавить в чтение», «Отклонить»; до нажатия на
  сервер ничего не уходит

#### Scenario: Запрещённая команда

- **WHEN** просят `rm -rf /var/lib/docker`
- **THEN** отказ сразу с объяснением, попытка в журнале

#### Scenario: RouterOS print

- **WHEN** модель просит `/interface wireguard peers print detail` на
  MikroTik
- **THEN** команда попадает в круг чтения по маске `/* print*` и выполняется
  сразу

#### Scenario: Сброс роутера

- **WHEN** модель просит `/system reset-configuration`
- **THEN** отказ сразу по списку «никогда», в журнале видна причина
