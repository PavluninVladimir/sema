## Context

Мотивация — в proposal.md. Что есть сейчас:

- Житель машины (репозиторий `sema-agent`) отдаёт карточки `symbols`,
  `context`, `impact`, `definition`, `diagnostics`, `search` через MCP по
  stdio; хук `semaagent -hook session-start` возвращает клиенту JSON с
  `additionalContext` — это единственное, что агент разработки видит
  автоматически.
- Знание о месте — у Сёмы: `memory_places` (репозиторий, файл, символ,
  источник, `checked`), `PlaceKnowledge`, `CodeKnowledge`,
  `AttachToPlace` с пределом `code.knowledge_chars` (1500). Житель
  спрашивает по проводу методом `память.code_knowledge`. 127 из 131
  привязок без репозитория — `repoByPath` узнаёт только хвост
  `server|app|agent`.
- Счётчик `~/.sema-agent/savings.json`: `calls=5`, `saved_lines=1483`,
  `card_lines=168` за всю историю; `code_knowledge` звали дважды.
- У Claude Code инструменты MCP отложены и невидимы модели до
  `ToolSearch`; у Codex — видимы сразу.
- CLAUDE.md зонтика — 1791 строка; абзацы «Архитектуры» называют пути
  вида `api/ui.go`, `engine/queue.go`, `store/queue.go`.

## Goals / Non-Goals

**Goals:**

- Три шага, каждый со своим замером; следующий — только если предыдущий
  сдвинул счётчик.
- Одна дверь: агент разработки получает понимание места одним вызовом.
- Принципы приходят в карточку без ручной разметки, но человек видит их
  источник и может снять.

**Non-Goals:**

- Правка CLAUDE.md, AGENTS.md и промптов клиентов.
- Новый вид записи памяти «принцип»: привязка с источником «CLAUDE.md ·
  раздел» отличима и так; заводить вид — отдельное решение после того,
  как видно, что приложения читают.
- Замена `Read`/`Grep` у клиентов: карточки — подсказка, не запрет.
- Импорт спек OpenSpec в память (у них нет путей в коде; это следующая
  мысль, не эта).

## Decisions

**1. Подсказка живёт в ответе хука, а не в файлах проекта.**
CLAUDE.md читает один клиент в одной папке; ответ хука приходит всем
(Claude Code, Codex, subagent через `SubagentStop` — нет, ему хук старта
не приходит, см. риски) и в любой папке с выданными областями. Текст
подсказки — константа жителя машины с пометкой клиента: для Claude Code
добавляется строка про `ToolSearch`, для Codex — нет. Альтернатива —
строка в CLAUDE.md — отвергнута владельцем и не покрывает Codex.

**2. Шаг В измеряется до шага А.** После выката подсказки неделя
наблюдения за `savings`: число вызовов карточек за период (сейчас
счётчик накопительный — нужна разбивка по дням, самое простое —
строка в день в том же JSON). Порог для перехода к А не назначается
заранее: цифра «пять за месяц» такова, что любое движение будет видно.

**3. Приложение собирает житель машины, одним запросом.** Карточка знает
свои места: папка файла, файл, символы (у `symbols` — все объявленные,
у `context` — один). Житель шлёт по проводу `память.code_knowledge` с
полем `places: [{dir}, {file}, {file, symbol}...]`; Сёма отвечает одним
текстом в пределах `code.knowledge_chars`, порядок — точное раньше
общего (символ → файл → папка), внутри — подтверждённое и свежее раньше.
Альтернатива — клиент зовёт `code_knowledge` сам — это и есть нынешнее
положение с двумя вызовами за месяц.

**4. Приложение не задерживает карточку.** Запрос по проводу идёт с
коротким сроком (`agent.card_knowledge_ms`, по умолчанию 800 мс);
истёк или связи нет — карточка уходит с пометкой «память недоступна» и
без приложения. Ждать нельзя: карточка обещает быть дешевле файла, а
дешевле — это и быстрее. Пометка обязательна: молчание неотличимо от
«ничего не известно» (тот же принцип, что у диагностики ярусом ниже).

**5. Папка — четвёртый уровень привязки, не новая таблица.**
`memory_places` получает `dir` (относительный путь папки от корня
репозитория); `PlaceKnowledge` принимает список мест и ищет по `dir`
префиксом до ближайшей заведённой папки (не по всем родителям: принцип
`internal/` не должен приходить к каждому файлу сервера). Репозиторий
определяется по git-корню, который житель уже вычисляет (`WorkRoot`), и
передаётся явно — `repoByPath` по хвосту пути уходит.

**6. Принципы из CLAUDE.md разбирает житель, хранит Сёма ссылкой.**
Житель при старте сессии и по изменению файла (mtime) разбирает CLAUDE.md
зонтика: абзац → пути в обратных кавычках вида `pkg/file.go` или `pkg/`
→ привязка `{dir|file, source: "CLAUDE.md · <заголовок абзаца>", hash,
text: первое предложение абзаца}`. В память идёт одна строка, не абзац
(спека: ссылка, не копия). Сёма по хэшу решает: та же — ничего, новая
при старом заголовке — новая версия с `supersedes`, заголовка больше нет
— пометка «устарело». Снятое человеком помнится по паре «заголовок +
хэш» в `outside_acts` (как свёртки сводок) и не заводится снова.
Альтернатива — писать принципы руками с экрана — остаётся возможной
поверх, но стартовать с пустой памяти принципов значит стартовать с
нуля.

**7. Порядок в приложении и предел.** Символ → файл → папка; внутри
уровня — `confirmed DESC, id DESC`. Предел общий `code.knowledge_chars`,
строка «ещё N записей — `code_knowledge`» остаётся. Отдельного предела
для принципов нет: если принципы вытесняют уроки, это видно и правится
настройкой, а не новым кодом.

## Risks / Trade-offs

- [Подсказку не слушают] → неделя замера с разбивкой по дням; если
  счётчик не сдвинулся — А и Б не делаются, ищем причину (возможно,
  отложенные инструменты не грузятся даже по подсказке).
- [Субагенты не получают хук старта] → они и подсказки не увидят; это
  известная грабля («Субагент память не спрашивает»), покрывается строкой
  в задании субагенту, не этим изменением.
- [+1 запрос по проводу на карточку] → срок 800 мс и отдача без
  приложения при истечении; провод и так живёт с пингом раз в две
  минуты.
- [Разбор CLAUDE.md наплодит привязок] → только абзацы с путями в
  обратных кавычках; один абзац — одна запись на каждый названный путь;
  привязки с источником «CLAUDE.md» отличимы и снимаются с экрана.
- [Приложение выдаёт секретное облачной модели] → приложение идёт через
  ту же `Recall` с областями и классом; принципы из CLAUDE.md — область
  «код», класс считается как у любой записи.
- [`repo` в старых привязках пуст] → запрос допускает пустой `repo`,
  как сейчас; новые заводятся с репозиторием от git-корня.

## Migration Plan

1. Житель машины: подсказка в ответе хука + счётчик по дням. Выкат —
   `launchctl kickstart`. Откат — прежняя сборка.
2. Неделя наблюдения (`savings.json`, строка на «Агентах»).
3. Сёма: `memory_places.dir`, `PlaceKnowledge` по списку мест, метод
   провода с `places`; житель: приложение к карточке. Старый
   `code_knowledge` работает как прежде — совместимость по обе стороны
   провода: житель без `places` получает старый ответ.
4. Житель: разбор CLAUDE.md, Сёма: приём привязок по хэшу; экран
   «Память» показывает источник и даёт снять.
