## Context

Подключение бота содержит подтверждённый внешний ID и отдельный зашифрованный токен. Для приёма обновлений нужен адрес Сёмы, доступный Telegram по HTTPS.

## Goals / Non-Goals

Принимать обновления Bot API и применять выбранные функции. Выполнять команды управления по сессии владельца или программному токену с правом управления ботами Telegram. Подключения Telegram через личный аккаунт обслуживаются отдельно.

## Decisions

- Формировать URL от настроенного origin Сёмы. Регистрировать через setWebhook с отдельным секретом заголовка. Сравнивать хэш секрета до чтения тела. Отклонять включение, когда у бота уже зарегистрирован другой адрес.
- Сохранять конфигурацию отдельно от токена. Сетевые изменения конфигурации сериализовать. После отказа Telegram сохранять прежнее локальное состояние.
- Запоминать идентификаторы доставок с отметками времени. При приёме новых обновлений удалять метаданные старше 48 часов. Данные нужны для дедупликации и счётчика флуда. Тексты входящих сообщений не записывать.
- В группах выполнять функции только по явному списку ID. Перед удалением проверять роль автора в Telegram и пропускать администраторов. Команды и личный автоответ настраивать отдельно.
- Управление из UI и HTTP использует общие операции. Токен бота и секрет webhook отсутствуют в ответах и ошибках.
- В карточке API выводится отдельной секцией. URL для `GET` и `PATCH` берётся от адреса Сёмы, отправка сообщения доступна по `/send`. Право `telegram_bots` действует только на маршрутах этого API и использует обычную выдачу и отзыв токенов Сёмы.

## Risks / Trade-offs

Повтор доставки не должен повторять исходящее действие. Если ответ на внешнее действие потерян, статус отмечает ошибку и повтор не отправляет второе сообщение. Telegram требует право удаления сообщений для антиспама.

## Migration Plan

Пустое состояние оставляет функции и webhook выключенными у существующих подключений. Удаление подключения снимает ранее зарегистрированный этой Сёмой webhook.
