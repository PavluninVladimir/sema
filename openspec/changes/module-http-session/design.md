## Context

Зачем — см. proposal.md. Инструменты песочницы — реестр `script.Tool`
(`engine/scripts.go`), функция получает аргументы JS и возвращает значение
Go, которое goja переводит в JS; функции Go в возвращённом значении
становятся функциями JS. Ошибка инструмента с меткой `toolErrMark`
считается ошибкой инструмента и модуль не выключает; исключение без метки —
сломанный код.

## Decisions

1. **Сессия — объект с методами** `get(url, {headers})`,
   `post(url, body, {headers, contentType})`,
   `request(method, url, body, {headers, contentType})`, а не номер сессии
   параметром: так модель пишет код короче и не путает сессии. Внутри —
   `http.Client` с `cookiejar` и транспортом `scriptHTTP` (охрана адресов,
   перенаправления в пределах того же сайта). Живёт столько, сколько вызов
   модуля: между запусками cookie не хранятся — вход заново.
2. **Ответ — значение, а не исключение**: `{ok, status, headers, body, url,
   error}`. Методы сессии — функции Go без метки ошибки инструмента, и
   исключение из них выключило бы модуль за чужой сервер. Исключение — только
   на неверных аргументах (нет адреса).
3. **Set-Cookie в заголовках ответа нет**: cookie держит сессия, а
   заголовки ответа идут в журнал и к модели — номер сессии там не нужен.
4. **Тело-объект**: при `contentType` формы — кодируется формой, иначе JSON.
5. **Хеши** — `crypto.md5|sha1|sha256(text, {encoding})`, кодировка через
   `golang.org/x/text` (уже в зависимостях), без права.

## Risks / Trade-offs

- [Модуль уносит cookie чужого сайта в журнал] → Set-Cookie не отдаётся,
  маски журнала прежние.
- [Сессия обходит охрану] → тот же транспорт, что у `sema.http.*`.
