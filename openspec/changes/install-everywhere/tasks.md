## 2. И2 · Остановка, WAL и инвариант очереди

- [x] 2.1 «закрыт чисто» пишется последней транзакцией перед закрытием базы, замок снимается после; checkpoint WAL — `CheckpointLog` со сроком 10 с перед отметкой (см. 2.8), порядок в `cmd/sema/main.go`
- [x] 2.1a при старте признак читается: «прошлый запуск закрылся неначисто» пишется в журнал
- [x] 2.2 мягкий срок — настройка `stop.soft_s` (30 с) вместо зашитых пяти секунд
- [x] 2.3 `stop_grace_period: 150s` в compose и `--stop-timeout 150` у запущенного контейнера
- [x] 2.4 аренда возвращается по сроку сама, без участия бравшего; точность аренды поднята до наносекунд — до этого «срок вышел» врал в пределах секунды (`TestLeaseReturnsWithoutHolder`)
- [x] 2.5 Внутренние работы очереди повторяемы: разбор памяти и учёба берут только неразобранное/недублирующее, опрос трекеров — по уникальному ключу задачи, а свёртка сводки идёт через `outside_acts` с заметкой-результатом — повтор после сбоя между записью в память и заменой сводки не пишет вторую запись и не ходит к модели снова (`TestFoldIdempotentAfterFailure`). Строка очереди закрывается одним UPDATE (`FinishWork`)
- [x] 2.6 внешние действия: `outside_acts` с ключом и отметками «делаю» / «сделано» до записи результата; перенос письма в спам уже идёт через них (ключ — Message-ID, потому что UID меняется)
- [x] 2.6a проверено честно: база закрывается между внешним действием и записью результата, повтор видит «сделано» и дописывает результат вместо второго переноса (`TestOutsideActionNotDoneTwice`, `TestKilledMidOutsideAction`)
- [x] 2.7 нечистое закрытие при старте — `PRAGMA quick_check` и запись в журнал; на аккуратный выход не рассчитываем
- [x] 2.8 checkpoint журнала предзаписи со своим сроком (10 с); не успел — закрываемся всё равно, дочитается при следующем открытии
**Ворота И2:** сто остановок подряд, включая жёсткие, не теряют работ и не
оставляют несведённого журнала предзаписи.
