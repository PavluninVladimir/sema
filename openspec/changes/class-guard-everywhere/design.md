## Context

Проверка «что можно отдать облачной модели» живёт в `engine/classes.go`
функцией `outsideCut(cloud, class, sender)`. Её зовут ровно три места, и все
три — сборка контекста: `chat.go`, `memory_chat.go`, `files.go`. Фоновые
дороги к модели проверки не знают:

```
письмо  ── poll ─────→ classify(provider(ActiveProvider()))  ← проверки нет
картинка ── AddFile ──→ imageText → llm.SeeImage             ← только бюджет
любой текст ─────────→ embedder.Embed                        ← ничего
```

Три обстоятельства делают починку нетривиальной:

1. **Класс файла считается по тексту, который добывает модель.** `ClassOfFile`
   смотрит `Filename + Extracted`, а `Extracted` у картинки берётся из ответа
   модели. Порядок надо разворачивать, иначе решение принимается после того,
   как данные уже ушли.
2. **Домашняя модель может отсутствовать.** После переезда на Pi это обычное
   состояние, а не исключение. Значит «нет домашней» — законный исход, у
   которого должно быть понятное поведение, а не тихий обход правила.
3. **Эмбеддер — не модель из справочника.** Он настраивается строкой в
   `config.yaml` и не проходит через `ModelIsCloud`.

## Goals / Non-Goals

**Goals:**

- Одна точка проверки, через которую физически проходят все дороги к модели.
- Класс сущности известен до обращения к модели, а не после.
- Отказ виден: человек понимает, что не было показано и почему.

**Non-Goals:**

- Не делаем два эмбеддера (сетевой для обычного, домашний для секретного):
  это разные векторные пространства, искать по ним вместе нельзя.
- Не трогаем согласие по чувствительному — механизм `class_consent` остаётся
  как есть.
- Не переписываем `sentClass` на модель: приметы остаются строковыми.

## Decisions

### Одна дверь вместо трёх проверок

Вводится `Engine.mayGoOutside(kind string, id int64, model string) (bool, string)`:
она сама достаёт класс сущности, сама узнаёт у `ModelIsCloud`, куда идёт
вызов, и возвращает решение с причиной. `outsideCut` остаётся её внутренней
частью — правила не раздваиваются.

Альтернатива «проверять в `llm.OnCall`» отвергнута: там уже поздно, запрос
отправлен, а отменить его нельзя.

### Порядок для картинки: OCR → класс → модель

`imageText` меняет порядок на обратный нынешнему:

```
ourOCR(path) → предварительный класс(имя файла + текст OCR)
             → секретное? модель не зовём вовсе, возвращаем текст OCR
             → иначе зовём модель, как раньше
             → окончательный класс по полученному тексту (только вверх)
```

Расход не растёт: наш OCR и сейчас работает всегда — его текст уходит модели
подсказкой. Меняется только момент, когда мы смотрим на результат.

### Картинка без текста — настройка, не гвоздь

`vision.no_text` со значениями `send` / `ask` / `hold`, по умолчанию `ask`.
Спрашивается через «Уведомления» тем же путём, что согласие по чувствительному.

### Разметка писем: роль плюс домашняя модель для закрытого

`classify` получает провайдера не от `ActiveProvider`, а от роли «Фильтр
писем». Для письма из закрытого ящика или класса «секретное» берётся домашняя
модель (`ModelIsCloud == false`); её нет — письмо получает
`StatusInboxOK` с причиной «домашней модели нет, наружу не отдаю». Это
согласуется с уже существующим поведением при отсутствии провайдера.

### Эмбеддер: признак дома по адресу

`embed.Embedder` получает поле `Outside`, вычисляемое один раз при создании:
адрес не в петле и не в частной сети — значит наружу. Секретное такому
эмбеддеру не отдаётся, запись остаётся без вектора, отказ пишется в журнал
памяти или отправленного (по виду сущности).

Признак считается по адресу, а не настройкой: человек не должен помнить,
что он поменял `base_url` и тем самым открыл дверь.

### Журнал: класс от сущности

`llm.Call` получает необязательные поля `ClassKind` / `ClassID`. Заполняет их
тот, кто зовёт модель и знает, о какой сущности речь. Пусто — журнал считает
класс по тексту, как сейчас.

## Risks / Trade-offs

- **Письма закрытого ящика перестанут размечаться**, если домашней модели нет.
  Это осознанный размен: неразмеченное письмо во «Входящих» лучше утечки. На
  экране «Почта» такие письма видно по причине.
- **Приметы документов дадут ложные срабатывания** — например, слово «полис» в
  обычной переписке поднимет класс до секретного, и картинка не уйдёт модели.
  Понижение классом занимается человек, и это ровно тот случай.
- **Порядок OCR-первым замедляет разбор картинок** на время работы tesseract
  даже там, где класс обычный. На Pi это единицы секунд в фоновой очереди.
- **`mayGoOutside` легко забыть** в новом коде. Защита — тест, который
  перебирает вызовы `llm.` в пакете `engine` и требует, чтобы рядом стояла
  проверка; такой тест ловит появление четвёртой двери.
