## 1. Вход: умолчания и код первой установки (спека access-control)

- [ ] 1.1 Умолчания `auth.local_open` → `false` и `auth.local_scope` → `loopback` — через реестр умолчаний, а не литералами в `internal/auth/auth.go`.
- [ ] 1.2 Разовая миграция при старте: база с данными (ящики, ключи или сессии), где эти ключи не записаны, получает явные `true` и `private`. Пустая база получает новые умолчания.
- [ ] 1.3 Защищённый порт по умолчанию — `127.0.0.1:8443` (`config.go`); в примерах Docker адрес задаётся явно.
- [ ] 1.4 Код первой установки: создаётся при старте, пока ключей нет; выводится в stdout с адресом входа. Умирает после первого ключа, по сроку и при перезапуске. Предел попыток — общий с фразой.
- [ ] 1.5 Страница входа: поле кода первой установки, пока ключей нет. Сессия по коду — только заведение ключа, тот же урезанный вид, что у фразы снаружи.
- [ ] 1.6 `canRegister`: первый ключ — с loopback, из сессии, по фразе или по коду; из частной сети — только при включённом «частная сеть — своя».
- [ ] 1.7 Переключатель «частная сеть — своя» на «Вход и доступ» — с вопросом, который называет, кто получит доступ без ключа.
- [ ] 1.8 Маска журнала (`internal/journal`) пропускает код первой установки только в строке его выдачи; в журнал доступа идут использование и отказы, но не код. Тест рядом с `TestSecretsNeverReachLog`.
- [ ] 1.9 Тесты по сценариям спеки: свежая установка закрыта; обновлённая — как была; сосед по сети без кода не заводит ключ; код после первого ключа не принимается; подбор кода запирается. Оба `security_regress_test.go` зелёные.
- [ ] 1.10 На живой Сёме (Pi) до выката: после обновления своя сеть по-прежнему входит без ключа, на «Вход и доступ» это видно.
