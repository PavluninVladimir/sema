## Why

Владелец открывает исходники Сёмы на GitHub под AGPL-3.0 и оставляет за
собой право позже продавать коммерческую лицензию. Сегодня код к этому не
готов:
- в git лежат бинарники;
- в тестах и макетах — личные данные владельца: домены, почта, телефон,
  фамилия, имена серверов, живые снимки экранов;
- в коде есть привязки к его собственным модулям и серверу MCP;
- путь модуля Go не совпадает с GitHub.

Главное: по умолчанию Сёма пускает без ключа любого из частной сети. Это
разумно для одного владельца дома и опасно для любого, кто поставит её у
себя.

## What Changes

- **Два публичных репозитория с чистого первого коммита**:
  - `sema` — нынешний зонтик: `server/`, `openspec/`, `design/` и
    `docs/`, где будет переложенный `CLAUDE.md`;
  - `sema-agent` — житель машины целиком, с интеграциями для Claude Code и
    Codex.

  История нынешних репозиториев не публикуется и сохраняется локально
  bundle-файлами.
- **Лицензия AGPL-3.0-only** в обоих репозиториях:
  - дополнительное разрешение по §7: модули и скиллы пользователя —
    отдельные работы;
  - встроенные скиллы — под CC0 1.0;
  - `NOTICE` и `THIRD_PARTY` для зависимостей, шрифтов и htmx;
  - чужие правки — только с подписанным CLA.
- **Без личного и внутреннего.** Из публикации убираются личные данные, твои
  модули и привязки к твоему серверу MCP, живые снимки, `config.yaml`,
  `.env`, `.claude/`, `CLAUDE.md` и следы агентов разработки в коммитах.
  Тесты и макеты обезличиваются. Чтобы личное не утекло снова, у владельца
  локально стоит стоп-лист.
- **BREAKING для новых установок: безопасные умолчания входа.** Вход без
  ключа из частной сети по умолчанию выключен. Первый ключ заводится с
  самой машины (loopback) или по одноразовому коду первой установки из
  журнала процесса (`docker logs`). Защищённый порт слушает только
  loopback. Уже работающие установки сохраняют прежнее поведение.
- **Ссылка на исходники в интерфейсе** (AGPL §13): «Исходный код» ведёт на
  репозиторий и версию работающей сборки.
- **Путь модуля Go** — `github.com/PavluninVladimir/sema/server` и
  `github.com/PavluninVladimir/sema-agent`.
- Файлы публичного репозитория:
  - `README` на двух языках;
  - `CONTRIBUTING` с CLA;
  - `SECURITY.md`;
  - `.env.example`;
  - CI: сборка, тесты, `go vet`, сканер секретов.

## Capabilities

### New Capabilities
- `source-availability`: где в интерфейсе ссылка на исходный код
  работающей версии, что она содержит и откуда берёт версию.

### Modified Capabilities
- `access-control`: умолчания входа для новой установки — без ключа из
  частной сети нельзя, первый ключ только с loopback или по коду первой
  установки. Прежние установки сохраняют своё поведение. Требование «Вход
  по passkey» меняет и `login-phrase`, поэтому его архивируют первым.

## Impact

- Код сервера:
  - `internal/auth`, `api/auth.go`, `store/setting_defs_auth.go` —
    умолчания входа;
  - `config.go` — адрес защищённого порта;
  - `internal/version` и экран — ссылка на исходники;
  - `store/mcp.go` — привязка к своему серверу MCP;
  - подсказки на экранах интеграций;
  - встроенный скилл `linux-admin.md`;
  - ~60 тестов с личными данными;
  - `go.mod` и импорты — 461 файл.
- Код агента: `go.mod`, `deploy/` (адреса, имя plist), примеры
  интеграций с путями владельца.
- Репозиторий: `.gitignore` и бинарники, `Dockerfile` (`TZ`,
  `SEMA_HOST_ALIAS`), `docker-compose.yml` (`~/Scans`).
- Документы: `CLAUDE.md` → `docs/`; `openspec/` и `design/` обезличиваются,
  живые снимки и скриншоты не публикуются.
- Вне кода:
  - новые репозитории на GitHub;
  - CLA Assistant;
  - личная почта для коммитов;
  - стоп-лист у владельца.
