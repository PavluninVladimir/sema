## Context

Зачем — см. proposal.md. Здесь то, что определяет устройство.

- **Как шлюз вносит запросы сейчас** (`engine/agent_gateway.go`). Сёма
  сама звонит шлюзу и на каждый поток браузера открывает соединение к
  нему. `openGatewayStream` набирает **свой же HTTP-порт по петле**
  (`GatewayUpstream` = `127.0.0.1:8765`) и гонит байты в обе стороны.
  Поэтому для Сёмы каждый запрос из интернета приходит от 127.0.0.1, то
  есть «с этой машины». От входа без ключа сегодня защищают две настройки
  человека: выключить `auth.local_open`, включить `auth.trust_proxy`
  (задача 7.1 `agent-gateway`).
- **Что слушает Сёма:**
  - `:8765` — HTTP;
  - `:8443` — свой TLS (`api.ServeTLS`), HTTP/2;
  - `:8766` — провод агентов, TLS со взаимной проверкой (`agents.listen`).

  На Pi все три опубликованы на `0.0.0.0`.
- **Житель машины на маке** звонит Сёме на `:8766` и держит провод
  (`internal/link`). Вход по приглашению идёт по HTTP
  (`semaagent -enroll … -sema http://…:8765`, `/api/agents/enroll`) — это
  единственный путь без сертификата.
- **VPS-шлюз** (`internal/gate`): по `agent-gateway`, решение 9, край
  держит nginx. Он держит 80 и 443, certbot продлевает сертификат на
  `sema.example.org` до 26 декабря, nginx проксирует на шлюз
  (`127.0.0.1:8770`). Отсев известных путей (`semaPaths`) — у шлюза.
- **Ключи входа** привязаны к `auth.rp_id`, сейчас это `sema.local`.
  `login-phrase` описывает переезд на домен: вход фразой, ключи заново.
- **Подписки на пуши** привязаны к источнику страницы. Смена адреса —
  новые подписки, прежние умрут (404/410 от службы удалят их сами).
- **Сеть мак → Pi**: по замеру 3 октября 2026 `ping` в среднем 108 мс с
  всплесками до 851 мс. Прямой провод мака к Pi никуда не уходит, просто
  перестаёт быть единственным.

## Goals / Non-Goals

**Goals:**
- Ни одного HTTP-порта Сёмы в сети: снаружи — только 443 на VPS, дома на
  маке — 443 на петле мака, у Pi наружу — только провод агентов.
- Поток от шлюза **никогда** не считается «с этой машины» — построением, а
  не настройкой.
- Один адрес `https://sema.example.org` на маке и телефоне, дома и
  снаружи.
- Аварийный вход есть и требует SSH к Pi.

**Non-Goals:**
- Шлюз на Pi для телефона дома: позже, отдельным шагом, если понадобится.
- Провод жителя машины через VPS (память Claude Code в дороге): отдельное
  изменение.
- Сквозное шифрование до Pi: на VPS TLS кончается, и это названная цена
  `agent-gateway`, решение 5.
- Публикация готового образа, режим для чужих установок: это
  `open-source`. Там «только через шлюз» — один из способов установки.

## Decisions

### 1. Потоки шлюзов — свой вход в процессе, а не свой же порт по петле

```
 VPS-шлюз ==туннель==> Сёма: поток ---+
                                      +--> gatewayListener (chan net.Conn)
 мак: шлюз ==провод :8766==> поток ---+         |
                                                v
                                  http.Server{Handler, ConnContext: «шлюз:<имя>»}

 петля контейнера 127.0.0.1:8765 --> тот же Handler, «с этой машины» (проверка здоровья)
 петля Pi 127.0.0.1:8765 (публикация docker) --> «аварийный» (только через SSH)
```

`openGatewayStream` больше не набирает свой порт: соединение из туннеля
кладётся в `gatewayListener` — `net.Listener` поверх канала. Его
обслуживает отдельный `http.Server` с тем же обработчиком.

`ConnContext` помечает каждое соединение: «шлюз VPS», «шлюз мака»,
«аварийный», «петля контейнера». Решения входа читают **метку**, а не
адрес:
- поток шлюза никогда не «с этой машины»;
- `X-Forwarded-For` доверяется только на входе шлюза (настоящий адрес
  человека ставит шлюз), а на остальных — нет.

`auth.trust_proxy` как общий переключатель уходит: доверие — свойство
входа.

Альтернатива — оставить набор своего порта и заставить человека
выключить `local_open`. Отвергнута: одна забытая галочка открывает Сёму
всему интернету, а поток, пришедший с петли, неотличим от настоящего
локального.

### 2. Что слушает Сёма

- **Петля контейнера, `127.0.0.1:8765`**: проверка здоровья Docker и
  разбор на месте (`docker exec`). Вход по метке «петля контейнера».
- **Публикация docker — только `127.0.0.1:8765` хоста** Pi, не
  `0.0.0.0`. Docker вносит такие запросы от адреса моста (172.x), поэтому
  вход определяется по метке: отдельный слушатель контейнера на своём
  порту, опубликованный только на петлю хоста. Метка — «аварийный».
- **`:8443` и `api.ServeTLS` снимаются.** TLS для браузера держат шлюзы.
- **`:8766` (провод агентов) остаётся опубликованным в домашней сети** —
  это сам «агент», TLS со взаимной проверкой, без HTTP.

`-doctor` проверяет и называет всё, что слушает не на петле, кроме провода
агентов.

### 3. Аварийный вход

`ssh -L 8765:127.0.0.1:8765 pi`, затем `http://localhost:8765` на маке. На
«аварийном» входе контрольная фраза открывает **полную** сессию: дойти
сюда можно только с ключом SSH к Pi, а это сильнее фразы. Ключи входа
здесь не работают (другой адрес) — и не нужны. Строка на «Здоровье»:
«аварийный вход: последний раз …».

### 4. Шлюз на маке

```
 браузер мака --> sema.example.org --(/etc/hosts)--> 127.0.0.1:443
                                                          |
                                     житель машины, режим «локальный шлюз»
                                     TLS: лист от своего корня (Связка ключей)
                                                          |
                         провод к Сёме жив? --да--> поток по :8766 (звонит мак)
                                 |
                                нет (мак вне дома, Сёма недоступна)
                                 v
                         поток на https://sema.example.org (VPS) по IP VPS
```

- **Слушатель только `127.0.0.1:443`**, в сеть он не смотрит. Поэтому он
  живёт в процессе жителя машины. Запрет `agent-gateway`, решение 7, был
  про шлюз, который смотрит в интернет, и остаётся в силе для VPS. На
  экране «Агенты» это отдельная способность «локальный шлюз», и разрешает
  её человек.
- **Порт 443 без root.** macOS с 10.14 пускает непривилегированный
  процесс на порты ниже 1024. Подтвердить на машине владельца первым
  шагом, иначе — `launchd` с сокетом от системы.
- **Свой корень:** ECDSA P-256 с **ограничением имён** (Name Constraints)
  на `sema.example.org`, чтобы украденный корень не мог подписать чужой
  сайт. Корень лежит в `~/.sema-agent/` с правами 0600 и один раз
  кладётся в Связку ключей как доверенный для SSL: `security
  add-trusted-cert`, человек подтверждает паролем. Лист живёт 30 дней и
  перевыпускается сам. Корень агентов Сёмы для браузера не годится: он на
  Ed25519, а Chrome не принимает Ed25519 в сертификатах HTTPS.
- **Имя**: строка `127.0.0.1 sema.example.org` в `/etc/hosts`, один раз
  при установке, с паролем администратора. Строка не зависит от того,
  дома ли мак: на петле всегда отвечает свой шлюз, а куда отдать поток,
  решает он.
- **Поток по проводу.** На `:8766` появляется второй вид соединения —
  «поток», тот же приём, что у VPS-шлюза: первым кадром «зачем пришёл».
  Звонит мак, сертификат агента прежний. Сёма кладёт соединение в
  `gatewayListener` с меткой «шлюз мака».
- **Вне дома** поток уходит на VPS по адресу из настройки (по IP: имя
  на этом маке указывает на петлю), с проверкой настоящего сертификата
  домена. Это обычный HTTPS-клиент: адрес и ключи входа те же.
- **Отсев путей** (`semaPaths`) — тот же, что у VPS-шлюза: локальный шлюз
  не открывает больше, чем открыт край. Пределов частоты нет: в него
  ходит только свой браузер.

### 5. Вход агентов по приглашению

`/api/agents/enroll` идёт **через шлюз**: на маке — через локальный, но
провода у нового агента ещё нет, поэтому фактически — через VPS. Путь уже
в списке шлюза. Код приглашения одноразовый и живёт минуты, поэтому
интернет ему не страшен. Флаг `-sema` по умолчанию —
`https://sema.example.org`. Запасной путь — аварийный вход по SSH.

### 6. Адрес ключей входа и переезд

`auth.rp_id` и `auth.origin` — `sema.example.org`. Порядок:
1. `login-phrase` закрыт и архивирован, у владельца есть фраза.
2. Шлюзы работают.
3. Сменить адрес: Сёма предупреждает, что прежние ключи не пустят.
4. Войти фразой на маке (локальный шлюз) и на телефоне (VPS), завести
   ключи.

Прежние ключи не удаляются до подтверждения владельцем — откат возможен.

Подписки на пуши заводятся заново на новом адресе. Строка «Пуши на этом
устройстве» сама предложит подписаться (`pushOffer`).

### 7. Край — забота шлюза, а не Сёмы

Требование этого изменения к Сёме одно: у неё нет HTTP в сети. Что слушает
край, решает агент-шлюз (решение владельца 3 октября 2026).
- **Порт 80 у шлюза остаётся** под проверку сертификата Let's Encrypt
  (HTTP-01, certbot у nginx или ACME самого шлюза). Через него браузеру
  ничего от Сёмы не отдаётся.
- **DNS-01 через API регистратора домена не берём**: ключ API на VPS — это управление
  DNS всего `example.org`. Взлом VPS обошёлся бы дороже, чем открытый
  порт 80.
- **Для браузера — только 443 и HSTS** (`max-age=31536000` без
  `includeSubDomains`, чтобы не задеть соседние сайты на
  `example.org`): открывший адрес хоть раз сам не пойдёт на `http://`.

Правки края живут в спеке `agent-gateway` и в проекте жителя машины
(`internal/gate`, `deploy/`), а не в коде Сёмы.

## Risks / Trade-offs

- [Нет интернета — телефон без Сёмы; мак без Сёмы, если он не дома] →
  названо и принято. Дома мак ходит напрямую по проводу, пока он включён.
- [Трафик телефона открыт на VPS] → решение 5 `agent-gateway`, принято;
  дома на маке не так.
- [Украденный корень мака] → ограничение имён на один домен, 0600,
  короткий лист; отзыв — убрать корень из Связки ключей.
- [Порт 443 на маке не дадут без root] → проверка первым шагом, запасной
  путь `launchd` с сокетом.
- [Метка входа потеряется — поток станет «локальным»] → решения входа
  читают только метку; тест: поток из туннеля с подставленным
  `X-Forwarded-For: 127.0.0.1` и без него — не вошедший; оба
  `security_regress_test.go` зелёные.
- [Переезд адреса оставит без входа] → фраза до переезда, прежние ключи
  живут до подтверждения, аварийный вход по SSH.
- [Что-то ещё ходит в `:8765` по сети] → до снятия публикации — поиск по
  жителю машины и интеграциям (сейчас `-enroll` и пример в
  `install-mac.sh`) и журнал «Кто стучался» за неделю: кто приходил не
  через шлюз.

## Migration Plan

1. `login-phrase` закрыт, у владельца есть фраза.
2. Живой запуск VPS-шлюза (`agent-gateway` 7.1–7.6). Сёма пока
   доступна и дома по-старому.
3. `gatewayListener` и метки входа; `trust_proxy` по входу; тесты.
4. Локальный шлюз на маке: проверка порта 443, корень и Связка ключей,
   `/etc/hosts`, поток по проводу, переход на VPS.
5. Неделя журнала «Кто стучался»: кто ещё ходит не через шлюз.
6. Переезд адреса ключей на домен, ключи заново, подписки на пуши заново.
7. Снять публикацию `8765`/`8443` на `0.0.0.0` (оставить `127.0.0.1:8765`
   хоста), убрать `ServeTLS`. У шлюза — HSTS на 443; порт 80 остаётся его
   делом.
8. Проверка с другого устройства в домашней сети: `http://192.168.88.13:8765`
   и `:8443` — отказ соединения; `https://sema.example.org` с телефона и
   мака — работает; аварийный вход по SSH — работает.

Откат шагов 6–7: вернуть публикацию портов и `auth.rp_id` — прежние ключи
не удалены.
