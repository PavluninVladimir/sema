## Context

Публичный репозиторий имеет отдельную историю и основную ветку main. Рабочая установка Сёмы работает в Docker.

## Decisions

- Пакет привязан к SHA коммита. Публикация зависит от всех проверок и проверяет актуальность головы основной ветки. В метаданных GitHub и рядом с пакетом есть контрольная сумма.
- Сёма принимает сигнал о выпуске по HMAC SHA-256 с ограниченным временем жизни. Сигнал сообщает о версии. При включённой настройке Сёма атомарно создаёт пустой файл `request` в подготовленном каталоге `.release-webhook` тома данных. systemd на хосте замечает файл и запускает тот же установщик, который вызывается по резервному расписанию. Извещение и файл не выбирают источник или команду установки.
- Обновляющий процесс смотрит только последний выпуск заданного репозитория. Он проверяет пакет, сохраняет подключения и тома рабочего контейнера, проверяет новую версию в health и восстанавливает прежний контейнер при сбое.
- В «Работе Сёмы → Обновления» владелец видит URL, репозиторий и состояние webhook. Оба способа запуска делят блокировку установщика. Служба webhook ждёт блокировку, если расписание уже проверяет выпуск.

## Migration Plan

Первый выпуск готовится через pull request. Установку таймера и настройку ключа сигнала проверяют отдельно на сервере.
Службу срабатывания подготавливают отдельно на Docker-хосте. Приём ранее настроенного webhook и проверка по расписанию работают и без неё.
