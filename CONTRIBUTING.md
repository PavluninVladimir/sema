# Как участвовать

Спасибо, что хотите помочь Сёме. Здесь — порядок, проверки и правила, без
которых правку не примут. Устройство проекта — в `docs/ARCHITECTURE.md`,
команды — в `docs/COMMANDS.md`, грабли — в `docs/PITFALLS.md`.

*English speakers: issues and pull requests in English are welcome, but
the project language is Russian — comments, UI strings and OpenSpec
documents stay in Russian. Contributions require signing the [CLA](CLA.md).*

## Язык и имена

- Язык проекта — русский: комментарии, тексты интерфейса, журнал, спеки
  OpenSpec. Строка, которую увидит человек, — по-русски.
- **Имена в коде — латиницей**, общепринятыми словами. Слово для имени
  берётся из `docs/NAMES.md`, узел — из `docs/GLOSSARY.md`. Нового термина
  там нет — заведите его в той же правке. У слов вроде «итог», «срок»,
  «проверка», «отказ» по два-три смысла и разные английские слова: выбор по
  вкусу разводит родственные места так, что их не найти поиском.
- Русские имена в коде остались от прежнего порядка; переводите их по мере
  правок, а не отдельной массовой заменой. Не транслитерируйте.
- Сёма — он: в текстах интерфейса, подсказках и комментариях мужской род.

## Прежде чем писать код

- **Небольшая правка** (ошибка, опечатка, тест) — сразу PR.
- **Изменение поведения** — через OpenSpec: изменение в
  `openspec/changes/<имя>/` с `proposal.md`, `design.md`, `tasks.md` и
  дельтой спек. Его обсуждают до кода; так проще договориться, чем
  переписывать готовое.
- **Заметная правка интерфейса** начинается с макета в `design/`, и только
  потом переносится в код.
- Сомневаетесь — откройте issue и опишите, что хотите сделать.

## Правила проекта

- **Никакого cgo.** SQLite — `modernc.org/sqlite`, даты в базе — строки
  RFC3339. Зависимость с cgo не принимается: ломает кросс-компиляцию.
- **Ничего не забивать гвоздями.** Пороги, приметы, окна, сроки —
  настройки в реестре `store.SettingDef` или справочники в базе с экраном
  для правки. Число-умолчание рядом с чтением настройки роняет тест.
- **Письма из архива Сёмы не удаляются никогда** — удаление касается только
  почтового сервера.
- **Необратимое — только с вопросом**: удаление и массовый перенос в
  интерфейсе — с `Confirm` и осмысленным `ConfirmOK`.
- **К модели — только через дверь** (`engine/gate.go`): новый путь к
  модели или эмбеддеру не обходит проверку класса.
- **Сужение доступа** для уже работающих установок — настройкой со старым
  значением по умолчанию, а не переключателем в коде.
- **Секреты не попадают в журнал, на экран и в описание экрана** ни в
  каком виде. Новый вид секрета — новый случай в `TestSecretsNeverReachLog`.
- **Найденная дыра — новый тест** в `security_regress_test.go` того пакета,
  где она была.
- **Тестовые данные — только выдуманные**: `example.org`, `example.com`,
  `203.0.113.x`, `+70000000003`, «семья Ивановых». Ни настоящих адресов, ни
  имён, ни номеров документов.

## Проверки перед PR

Из `server/`:

```sh
gofmt -l .                       # пусто
go build ./...
go vet ./...
go test ./internal/...
```

Правили веб-клиент (`internal/web`) или экраны (`internal/api`) — ещё
браузерные тесты в настоящем Chrome:

```sh
SEMA_BROWSER=1 go test ./internal/api -run Browser -p 1 -timeout 45m
```

Переименовали символ — поищите его в строках тестов (тесты-сторожа ищут
имена строкой, компилятор их не видит) и в `docs/` (проверка — в
`docs/COMMANDS.md`, «Документация не врёт про имена»).

Тесты не заменяют проверку на живых данных: изменение поведения
проверяется против запущенного сервера (`curl` к `/api/ui` и
`/api/action`, `semacheck`). Напишите в PR, как проверяли.

## Коммиты и PR

- Один PR — одна мысль. Рефакторинг и исправление логики — отдельными
  коммитами: иначе не разобрать, от чего сломалось.
- Сообщение коммита — по-русски, о работе: что изменилось и почему.
- **Без подписей помощников и машинных трейлеров**: ни строк соавторства от
  инструментов, ни идентификаторов сессий, ни «сгенерировано тем-то».
  Сообщение говорит о работе, а не о том, кто держал клавиатуру. Ваше
  собственное авторство остаётся в поле автора коммита.
- PR с изменением поведения ссылается на изменение в `openspec/changes/`.

## Соглашение участника (CLA)

Чужие правки принимаются только с подписанным [CLA](CLA.md). Подпись —
один раз на человека через CLA Assistant: бот попросит её в первом же PR,
и без неё PR не сливается. Правки владельца проекта CLA не требуют.

**Зачем это нужно.** Сёма распространяется под AGPL-3.0-only, а владелец
проекта оставляет за собой возможность продавать коммерческую лицензию тем,
кому AGPL не подходит (двойное лицензирование). Для этого у него должно
быть право выпускать под другой лицензией весь код, в том числе ваш вклад.

**Что вы отдаёте и что остаётся у вас.** CLA — это лицензия, а не передача
прав, по образцу Apache ICLA:
- авторские права на ваш вклад остаются у вас; вы можете использовать его
  как угодно, в том числе в других проектах;
- владелец проекта получает бессрочную, безотзывную, неисключительную и
  бесплатную лицензию на ваш вклад с правом сублицензировать и
  перелицензировать его;
- то, что уже опубликовано под AGPL, под AGPL и остаётся: коммерческая
  лицензия появляется рядом с открытой, а не вместо неё.

DCO (подпись `Signed-off-by`) не используется: она подтверждает только
право отдать код под лицензией проекта и перелицензирования не даёт.

## Лицензия вклада

Ваш вклад входит в проект под AGPL-3.0-only с дополнительным разрешением по
разделу 7 (`LICENSE-EXCEPTION`). Правки встроенных скиллов
(`server/internal/engine/builtin/skills/`) дополнительно выходят под CC0
1.0, как и сами скиллы.

## Безопасность

Об уязвимостях не пишите в issues и PR — только приватным отчётом, как
описано в [`SECURITY.md`](SECURITY.md).
