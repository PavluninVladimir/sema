# Безопасность

Сёма держит у себя почту, ключи SSH, токены и пароли, поэтому дыры в нём
дороже обычного. Спасибо, что сообщаете о них приватно.

*English: please report vulnerabilities privately through GitHub Security
Advisories of this repository (Security → Report a vulnerability). Do not
open public issues for security problems.*

## Как сообщить

Только приватным отчётом через **GitHub Security Advisories** этого
репозитория: вкладка **Security → Report a vulnerability**. Отчёт видят
только сопровождающие проекта; в том же обсуждении договариваемся об
исправлении и о публикации.

Не открывайте issue, PR или обсуждение с описанием дыры до того, как она
исправлена.

Что приложить:
- версию — она видна в ссылке «Исходный код · версия» на странице входа и
  в настройках, и в выводе `sema -doctor`;
- как воспроизвести и что получает нападающий;
- без настоящих данных: письма, ключи и адреса замените выдуманными.

Получение отчёта подтверждается в обсуждении advisory. После исправления
advisory публикуется с описанием и, если хотите, с благодарностью вам.

Дыры в жителе машины — в репозиторий
[`sema-agent`](https://github.com/PavluninVladimir/sema-agent) тем же
способом.

## Какие версии поддерживаются

Исправления выходят для последнего релиза и ветки `main`. Старые версии
отдельно не исправляются — обновляйтесь.

## Что считается уязвимостью

Например:
- вход без ключа там, где его быть не должно: обход `protect`, passkey,
  токенов, контрольной фразы или кода первой установки;
- токен с узкими правами получает больше, чем `ScopeFor` его маршрута;
- данные класса «секретное» или из закрытого ящика уходят модели, которой
  человек не доверил закрытое, — мимо двери к модели;
- команда на сервере или вызов MCP выполняется мимо правил «Разрешить /
  Спросить / Запретить», команда с `sudo` проходит на сервер «без sudo»;
- модуль получает право, секрет или сервер, которые ему не выдали, или
  выходит из песочницы;
- HTML из писем исполняется в адресе Сёмы, путь к файлу выходит за
  хранилище, чужой сайт выполняет действие от имени вошедшего человека;
- секрет попадает в журнал, на экран, в резервную копию или в пуш;
- ссылка на файл открывает секретное или файл закрытого ящика;
- шлюз пропускает путь, которого нет в списке известных.

Не уязвимость — то, что человек разрешил сам: частная сеть, отмеченная
«своей», пускает соседей без ключа; доверенная модель видит закрытое;
сервер на уровне «полная» выполняет изменения по суду. Не уязвимость и
атака, для которой уже нужен полный доступ к машине Сёмы, её каталогу
данных и ключу шифрования.

## Безопасность по умолчанию

Новая установка закрыта:
- без ключа её пускает только сама машина (loopback); частная сеть
  становится «своей» только явным выбором на «Настройки → Вход и доступ»;
- защищённый порт по умолчанию слушает только loopback;
- новая модель заводится внешней, доверие выдаётся поштучно;
- команда, которой не подошло ни одно правило, запрещена;
- ночная смена на серверах работает вхолостую.

Установка, которая работала до появления этих умолчаний, сохраняет прежнее
поведение: при обновлении прежние значения записываются явно, и их видно
на «Вход и доступ».

## Код первой установки

В Docker браузер хозяина приходит в контейнер из сети моста, а не с
loopback, — значит, «с самой машины» первый ключ не завести. Для этого есть
одноразовый код.

- Пока не заведено ни одного passkey, Сёма при **каждом старте** создаёт
  новый код и печатает его в стандартный вывод вместе с адресом входа. Его
  видно в `docker logs` или в журнале службы.
- Код вводится на странице входа и открывает сессию, которой хватает
  **только на заведение ключа** — ни почты, ни секретов, ни настроек.
- Код перестаёт действовать после первого ключа, по истечении срока и при
  следующем старте процесса.
- На код действует тот же предел попыток, что на контрольную фразу:
  подбор запирает вход на растущий срок.
- В журнал доступа попадают использование кода и отказы, но не сам код.
  Маска журнала процесса пропускает код только в строке его выдачи.

Что из этого следует:
- пока первый ключ не заведён, журнал процесса — секрет: не публикуйте
  вывод `docker logs` и не отдавайте его в чужие системы сбора журналов;
- если журнал утёк до первого ключа — перезапустите Сёму: прежний код
  умрёт, будет напечатан новый;
- после первого ключа код из старого журнала ничего не открывает.

## Потеря всех ключей: `-reset-auth`

Запасной путь, когда не осталось ни одного устройства с passkey и нет
открытой сессии.

```sh
# Сёма остановлена; нужен доступ к каталогу данных
./sema-server -reset-auth -data /путь/к/данным

# в Docker
docker stop sema
docker run --rm -v sema-data:/data --entrypoint /usr/local/bin/sema \
  sema:latest -reset-auth -data /data
docker start sema
```

Команда удаляет **все passkey и все сессии**. После запуска вход снова как
у новой установки: с самой машины или по свежему коду первой установки из
журнала.

**Токены доступа и контрольная фраза при этом не удаляются.** Если сброс
понадобился из-за подозрения на утечку, после входа отзовите токены и
смените фразу на «Вход и доступ», а секреты — ключи моделей, пароли ящиков,
ключи SSH — замените у их владельцев.

Право на `-reset-auth` есть у того, у кого есть доступ к каталогу данных.
Поэтому каталог данных и ключ шифрования (`SEMA_KEY`) храните так же
бережно, как сами секреты: отдельно друг от друга, с правами только
владельцу.
